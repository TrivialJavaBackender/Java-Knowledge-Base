# Создать новый модуль

Создай новый interview prep модуль в `modules/$ARGUMENTS`.

## Модель работы — оркестрация, НЕ написание теории руками

**Главный агент только оркестрирует.** Он делает дешёвую работу (скаффолдинг, план
батчей, диспетчинг, агрегация коротких отчётов). **Каждый файл теории пишет отдельный
сабагент.** Так главный контекст остаётся лёгким, а перевод — единым.

> **Почему так.** Раньше главный агент писал все 8–15 файлов теории сам (по 150–300 строк
> каждый) → контекст раздувался, терминология дрейфовала между файлами, сессия дорожала.
> Делегирование решает все три проблемы сразу.

**НИКОГДА не пиши теорию в главном контексте.** Если тянет написать `theory/*.md`
самому — остановись и запусти сабагента (Фаза 3). Образец паттерна батчинга/волн —
`.claude/commands/check-translation.md`.

---

## Фаза 0 — Уточнение (главный агент, дёшево)

Спроси у пользователя:
- Имя модуля (папка в `modules/`) — обычно это `$ARGUMENTS`.
- Тема (краткое описание).
- Тип сборки: `kotlin` | `java-plain` | `java-spring` | `no-build`.
- **Список файлов теории с однострочной областью каждого** (например:
  `BASICS.md — иерархия кэшей, locality, метрики`).

## Фаза 1 — NO-OVERLAP + план батчей (главный агент, дёшево)

1. Прочитай `knowledge/GLOBAL_INDEX.md` и таблицу модулей в корневом `CLAUDE.md`.
2. Для каждой темы реши **OWN vs LINK**:
   - **OWN** — концепт ещё не имеет владельца → этот модуль становится владельцем.
   - **LINK** — концепт уже принадлежит другому модулю → даём ссылку, **не дублируем**.
     Зафиксируй точный путь цели (`modules/<slug>/theory/FILE.md`).
3. Сгруппируй файлы в батчи **адаптивно**:
   - по умолчанию **1 файл = 1 батч (= 1 сабагент)**;
   - тесно связанные файлы (≤3) объединяй в один батч ради общих перекрёстных ссылок
     (например `CACHE_PATTERNS.md` + `EVICTION_POLICIES.md`).
4. **Покажи пользователю** план батчей + решения OWN/LINK **до запуска сабагентов**.
   Это обязательный шаг ("сначала план — батчи с теорией").

## Фаза 2 — Скаффолдинг (главный агент, дёшево, без тяжёлой прозы)

Создай структуру директорий.

`kotlin` / `java-plain`:
```
modules/<name>/
├── theory/
├── pom.xml
└── src/
    ├── main/
    │   └── kotlin/exercises/   (или java/by/pavel/)
    └── test/
```
`java-spring`:
```
modules/<name>/
├── theory/
├── pom.xml
├── Dockerfile
└── src/main/
    ├── java/by/pavel/
    └── resources/application.properties
```
`no-build`:
```
modules/<name>/
├── theory/
└── exercises/
```

Затем:
- **`pom.xml`** — скопируй из соседнего модуля того же типа, адаптируй `<artifactId>`.
- **`README.md`** — описание, структура, команды сборки/запуска/тестов и (если есть
  упражнения) модуль-специфичный фокус code review. Прогресс НЕ трекаем — это web app.
- **`ROADMAP.md`** — **перечисли файлы теории в нужном порядке прохождения**.
  ⚠️ web-sync берёт порядок теории на сайте из первого упоминания `theory/<NAME>.md`
  в `ROADMAP.md`; сабагенты тоже опираются на этот список. Файлы не из roadmap уйдут
  в конец по алфавиту.

**Теорию, `INTERVIEW_QUESTIONS.md`, `_SUMMARY.md` здесь НЕ пиши.**

## Фаза 3 — Диспетч сабагентов теории (Opus, параллельно, ≤5, волнами)

Запусти по одному сабагенту на батч:
`Agent(subagent_type: "general-purpose", model: "opus", prompt: <см. шаблон>)`.

**Максимум 5 параллельно** (все Agent-вызовы в одном сообщении). Если батчей больше —
запускай волнами по 5, дожидаясь предыдущей волны.

### Шаблон промпта сабагента

---
Ты пишешь один или несколько файлов теории для interview prep репозитория. Пиши на
**естественном грамотном русском языке**.

**Сначала прочитай (обязательно):**
1. `knowledge/GLOSSARY.md` — правила перевода.
2. `knowledge/CANONICAL_TERMS.md` — каноническая терминология.
3. Релевантную часть `knowledge/GLOBAL_INDEX.md` — что уже принадлежит другим модулям.

**Контекст модуля:** `<name>` — `<тема модуля>`.

**Твой батч — написать файлы:**
- `modules/<name>/theory/<FILE>.md` — `<область из Фазы 0>`
- (…ещё файлы батча, если есть)

**Решения OWN/LINK для этого батча:**
- `<концепт>` — OWN (раскрываем здесь полностью).
- `<концепт>` — LINK на `modules/<slug>/theory/<FILE>.md` (только ссылка, без дублирования).

**Соседние файлы теории модуля** (для корректных относительных перекрёстных ссылок в
блоке "Где почитать дальше"): `<перечисли остальные theory/*.md модуля>`.

**Формат каждого файла** (как существующая теория, ~150–300 строк):
- Заголовок `# <Модуль> — <Тема>` (первая строка идёт в title на сайте).
- Содержательные разделы `##`; таблицы, блоки кода, примеры, "battle-stories" где уместно.
- Блок "## Где почитать дальше" с относительными ссылками на соседние файлы теории модуля.
- Блок "## Источники": official docs, engineering blogs, books/talks.
- Перекрёстные ссылки на другие модули — относительными путями (`../../<slug>/theory/X.md`).

**Перевод — строго по `GLOSSARY.md`:**
- Латиницей оставляй **только** раздел 1 (аббревиатуры/протоколы/продукты/алгоритмы:
  TCP, REST, Kafka, Redis, Raft, Bloom filter и т.д.) и содержимое code-блоков.
- Всё остальное — русский по разделу 2 (request → запрос, latency → задержка, …).
- Запрещены формы из раздела 3 (транслит-глаголы «стримит/фетчит/роутят», латиница в
  теле предложения, апостроф-формы `node'ы`).

**Пиши файлы инструментом Write.**

**Верни короткий отчёт (≤200 слов), БЕЗ полного текста файлов:**
```
- Файл: modules/<name>/theory/<FILE>.md
- Ключевые концепты: …
- Перекрёстные ссылки: …
- Кандидаты Q&A (2–3): Q… / A…
- В GLOBAL_INDEX добавить: <концепт> → modules/<name>/theory/<FILE>.md
```

## Фаза 4 — Агрегация (главный агент, дёшево, только из коротких отчётов)

> **Инвариант параллелизма.** Общие файлы (`INTERVIEW_QUESTIONS.md`, `_SUMMARY.md`,
> `GLOBAL_INDEX.md`, `CLAUDE.md`) пишет **только главный агент здесь**. Сабагенты их не
> трогают — иначе гонка записи. Каждый сабагент пишет лишь свои файлы теории.

Из собранных коротких отчётов (НЕ перечитывая полные файлы теории):
- **`INTERVIEW_QUESTIONS.md`** — ≥15 вопросов из кандидатов Q&A. Формат `qa-bold`
  (`### Q1:` / `**A:**`) либо формат модуля согласно `web/content.config.ts`. Номера Q
  уникальны.
- **`_SUMMARY.md`** — ≤2 КБ, структура: Core Model / Key Concepts / Important Invariants /
  Common Pitfalls / Related Modules.
- **`knowledge/GLOBAL_INDEX.md`** — дописать секцию `## <Модуль>` со строками
  `<концепт> → modules/<name>/theory/<FILE>.md`.
- **Корневой `CLAUDE.md`** — добавить строку только в таблицу модулей ("Структура").
  Концепт→файл идёт лишь в `GLOBAL_INDEX.md` (пункт выше); в CLAUDE.md его НЕ дублировать.

## Фаза 5 — Sync + перевод

1. Web-sync:
   ```bash
   cd web && node_modules/.bin/tsx scripts/sync.ts
   ```
2. Авто-запуск `/check-translation <name>` — финальный линт перевода по новому модулю.
   Спорные случаи покажи пользователю по протоколу той команды.

---

## Правило теории

Перед добавлением темы — сверься с `knowledge/GLOBAL_INDEX.md` (single source of truth,
включая секцию «Disambiguated Concepts»). Если концепт уже принадлежит другому модулю —
**ссылка, а не дублирование** (решение OWN/LINK в Фазе 1). При перекрытии с существующим
файлом >30% — расширяй существующий, а не создавай новый.

## Пример

```
/new-module algorithms
```
→ Фаза 0 уточняет тип (`kotlin`) и список тем → Фаза 1 показывает план батчей + OWN/LINK →
Фаза 2 ставит скаффолдинг → Фаза 3 запускает сабагентов (Opus) по батчам теории →
Фаза 4 собирает INTERVIEW_QUESTIONS/_SUMMARY/GLOBAL_INDEX/CLAUDE.md → Фаза 5 делает sync
и линт перевода.
