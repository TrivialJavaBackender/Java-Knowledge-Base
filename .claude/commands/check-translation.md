# Проверка и исправление перевода модуля по глоссарию

Проверь и **исправь** все .md файлы модуля `$ARGUMENTS` на соответствие правилам перевода из `knowledge/GLOSSARY.md`.

**Модель субагентов: sonnet** (паттерн-матчинг, не требует глубокого рассуждения).
**Максимум 5 параллельных батчей** — если файлов больше, запускай волнами по 5.

## Алгоритм

### 1. Валидация

- Проверь, что директория `modules/$ARGUMENTS/` существует
- Если не существует — выведи список доступных модулей и останови выполнение

### 2. Сбор файлов

Собери все .md файлы для проверки:
```bash
find modules/$ARGUMENTS/theory -name "*.md" -type f 2>/dev/null
ls modules/$ARGUMENTS/INTERVIEW_QUESTIONS.md 2>/dev/null
```

Исключи: `ROADMAP.md`, `README.md`, `_SUMMARY.md`.

### 3. Распределение и запуск субагентов

Раздели файлы на батчи по **2-3 файла**. Запускай **максимум 5 батчей параллельно** (все Agent-вызовы в одном сообщении) с параметром `model: "sonnet"`.

Если батчей больше 5 — запусти первые 5, дождись результатов, затем запусти следующую волну.

### 4. Промпт для каждого субагента

---

Ты — линтер и фиксер перевода. Прочитай `knowledge/GLOSSARY.md`, затем проверь и **исправь** следующие файлы: [СПИСОК ФАЙЛОВ]

**ВАЖНО: это НЕ тупой find/replace.** Замена должна быть грамматически корректной — соблюдай падеж, число, род, согласование с окружающим предложением. Результат должен читаться как естественный русский текст.

Пример: «увеличить throughput» → «увеличить пропускную способность» (В.п.), НЕ «увеличить пропускная способность».

**Что исправлять (однозначные случаи — исправляй сразу):**

**[A] Непереведённые термины** — английские слова из раздела 2 глоссария, использованные вместо русских эквивалентов вне code-блоков. Замени на каноническую русскую форму **в правильном падеже**.
Примеры: `latency` → «задержка/задержки/задержку...», `node` → «узел/узла/узлу...», `request` → «запрос/запроса/запросу...».

**[B] Запрещённые транслит-глаголы** — замени на правильные формы:
- «стримит» → «передаёт потоком»
- «фетчит» → «загружает/получает»
- «роутят» → «маршрутизируют»
- «апдейтит» → «обновляет»
- «реплеит» → «воспроизводит/повторяет»
- «буферизируют» → «буферизуют»
- «бутстрапит» → «инициализирует/запускает»
- «фолбэк» → «запасной вариант/откат»

**[C] Латиница в русских предложениях** — английское слово (не аббревиатура, не бренд, не в code-блоке) внутри русского предложения. Замени на русский эквивалент из глоссария, согласуя с контекстом предложения.
Примеры: «делает reconnect» → «переподключается», «такие requests» → «такие запросы», «с высоким latency» → «с высокой задержкой».

**[D] Апостроф-формы** — замени на русский эквивалент или корректный транслит:
`node'ы` → «узлы», `pod'ы` → «поды», `backend'ом` → «бэкендом».

**[E] Непереведённые заголовки/столбцы** — переведи на русский.
`## Delivery guarantees` → `## Гарантии доставки`, столбец `Pattern` → `Шаблон`.

**НЕ трогать:**
- Содержимое code-блоков (``` ... ```) и inline-кода (` ... `)
- Аббревиатуры из раздела 1: TCP, REST, ACID, CAP, MVCC, CDN, gRPC, JWT, OAuth2, CQRS, Saga, CDC, WAL и т.д.
- Имена продуктов: Kafka, Redis, PostgreSQL, ZooKeeper, Envoy, Nginx и т.д.
- Имена алгоритмов: Raft, Paxos, Bloom filter, Merkle tree, Geohash и т.д.
- HTTP-заголовки: `Cache-Control`, `ETag`, `Authorization`
- URL, пути файлов, JSON-ключи
- Разрешённые транслиты: дашборд, фаервол, оверхед, снапшот, алерт, кастомный, стики-сессия, коммитить, мёрджить, деплоить, пушить
- Специальные термины: heartbeat, service mesh, feature store, champion-challenger, push-уведомления, token bucket, leaky bucket, webhook
- Дефисные термины: Kafka-кластер, JWT-токен, gRPC-вызов

**СПОРНЫЕ СЛУЧАИ — НЕ исправляй, а собери в отдельный список:**

Спорным считается случай, когда:
- Слово НЕ в глоссарии, но выглядит как непереведённый английский термин
- Перевод неоднозначен (несколько возможных вариантов, ни один не в глоссарии)
- Английское слово используется как устоявшийся жаргон, но НЕ в списке разрешённых транслитов
- Заголовок частично на английском (смешанный)

**Порядок работы для каждого файла:**
1. Прочитай файл целиком (Read tool)
2. Если нарушений нет — перейди к следующему файлу
3. Однозначные нарушения — исправь через Edit tool (каждое исправление отдельным Edit-вызовом)
4. Спорные случаи — НЕ трогай, запиши в отчёт
5. Не переписывай файл целиком — используй точечные замены

**Формат отчёта:**
```
ИСПРАВЛЕНО:
- theory/FILE.md: N исправлений ([A]×2, [C]×1)
- theory/FILE2.md: ✅ чисто

СПОРНЫЕ (требуют решения пользователя):
- theory/FILE.md строка ~45: «throttling» — нет в глоссарии, возможные варианты: «ограничение» / «дросселирование» / оставить
- theory/FILE3.md строка ~12: «graceful» в «graceful shutdown» — перевести как «плавное завершение» или оставить?

ИТОГО: N исправлений, M спорных случаев
```

### 5. После завершения всех субагентов

**5a. Агрегированный отчёт исправлений:**

```
## Результат /check-translation $ARGUMENTS

| Файл | Исправлено | Категории |
|------|------------|-----------|
| theory/X.md | 3 | [A]×2, [E]×1 |
| theory/Y.md | 0 | ✅ |

**Итого: N исправлений в M из K файлов**
```

**5b. Спорные случаи — предложи пользователю:**

Собери ВСЕ спорные случаи из всех субагентов в единый список и покажи пользователю:

```
## Спорные случаи (требуют решения)

1. **«throttling»** (встречается в: theory/X.md:45, theory/Y.md:12)
   → Варианты: «ограничение скорости» / «дросселирование» / оставить как есть

2. **«graceful shutdown»** (theory/Z.md:78)
   → В глоссарии: «плавное завершение». Исправить?

3. ...
```

Спроси пользователя: для каждого спорного случая — исправить (и на что), добавить в глоссарий как разрешённый, или скипнуть?

После решения пользователя — примени оставшиеся исправления и при необходимости обнови `knowledge/GLOSSARY.md` (добавь новые термины в соответствующий раздел).
