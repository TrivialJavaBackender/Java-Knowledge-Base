# ci-cd — семантическое сжатие

Модуль о том, что физически происходит между `git push` и работающим сервисом на staging.
Ветвление и решение «когда катим» принадлежат `engineering-process`; рантайм-механика Docker,
Kubernetes, Helm и Terraform — `infrastructure`. Здесь — путь артефакта и цена каждого шага.

Сквозной пример всех двенадцати файлов: сервис `payments` (Spring Boot 3.3.4, Java 21, Maven,
PostgreSQL, пик 40 запросов в секунду, базовая сборка 12 минут). Учебные артефакты в `pipelines/`:
один конвейер на трёх языках, чарт Helm с окружениями, база и overlay kustomize, манифесты Argo CD,
стек Swarm, модуль Terraform.

## Core Model

**Артефакт рождается один раз и дальше только меняет упаковку:** jar → слои образа → дайджест →
манифест. Всё остальное в модуле — следствия этого утверждения и цена его соблюдения.

Три границы, из которых выводится почти вся механика:

1. **Задание — единица исполнения.** Шаги делят файловую систему, задания — нет. Отсюда
   параллельность, изоляция отказа, выбор образа, и необходимость явных кэша и артефактов.
2. **Исполнитель эфемерен.** Ничто не переживает границу задания само по себе. Состояние, которое
   должно пережить, обязано быть адресуемым снаружи — ключом кэша, именем артефакта, тегом кэша
   слоёв в реестре.
3. **Дайджест адресует содержимое, тег — нет.** Продвижение по окружениям и откат держатся
   исключительно на первом.

Конвейер — **граф зависимостей**, а не список этапов: длительность есть длина критического пути,
отказ распространяется по рёбрам, а «пропущено» и «упало» — разные состояния.

## Important Invariants

- **Собрать один раз, продвигать один и тот же артефакт.** Пересборка на окружение — не
  оптимизация, а потеря утверждения «на проде работает ровно то, что проверено на qa».
- **Образ адресуется дайджестом.** Тот же тег после пересборки указывает на другие байты, и ошибки
  не возникает нигде — вплоть до смеси подов со старым и новым кодом в одном окружении.
- **Конфигурация живёт снаружи артефакта.** Образ не знает, в каком он окружении; значения
  приезжают переменными окружения на старте и проверяются снаружи (`/version`).
- **Зелёный шаг раскатки без явного ожидания готовности ничего не доказывает.**
- **Длительность конвейера и длина цикла обратной связи — разные величины.** Оптимизируют вторую.
- **Раскатка не заканчивается применением манифеста.** Конвейер обязан дождаться вердикта и
  прервать раскатку при провале: контроллер про таймаут конвейера ничего не знает.
- **Доля трафика задаётся маршрутом, а не числом подов.** Без управления трафиком минимальная
  канарейка равна `1/N` по репликам.
- **Утверждение о поведении подпирается источником.** В разделе «Источники» каждого файла —
  только кликабельные URL: теорию читают в браузере с телефона.

## Common Pitfalls

Общее у большинства из них: **отказа нет, есть молчаливо неверный результат.**

- **`latest` или `dev` как адрес артефакта** — ломает и продвижение, и откат.
- **Кэш `~/.m2` при SNAPSHOT-зависимостях**: отметка «сегодня уже проверяли» восстанавливается
  вместе с кэшем, и Maven, соблюдая политику, собирает против вчерашней версии.
- **Неудавшаяся запись кэша не роняет сборку.** «Кэш не окупается» и «кэша никогда не было»
  снаружи выглядят одинаково — зелёным конвейером.
- **`terraform apply` без сохранённого плана** строит план заново по входам момента применения,
  а не по тем, что видел ревьюер: план смотрели с `dev.tfvars`, применили с `staging.tfvars`.
- **Проброс `/var/run/docker.sock`** в контейнер задания — выдача root на хосте: у API демона нет
  модели прав.
- **Собственный исполнитель на публичном репозитории.** Отсутствие секретов у форка сдвигает риск
  на шаг, а не убирает: машина не обязана быть чистой после чужого задания.
- **Ожидание, что Kubernetes сам откатит застрявшую раскатку.** Он выставит
  `ProgressDeadlineExceeded` и продолжит попытки.
- **`--atomic` в Helm 4** убран из справки, но принимается с предупреждением — одинаково у
  `upgrade` и `install`.
- **Ускорение задания вне критического пути.** Конвейер от этого не сокращается вовсе.
