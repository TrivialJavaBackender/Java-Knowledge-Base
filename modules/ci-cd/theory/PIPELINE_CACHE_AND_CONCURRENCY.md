# Что переживает границу задания и сколько это стоит

> **Какую проблему решает.** Кэш «настроен», а сборка идёт с нуля; образ собрался зелёным из чужого jar; тридцать заданий стоят в очереди к трём исполнителям, и две раскатки приезжают в одно окружение одновременно.
> **Кому это надо.** Тому, кто настраивает кэш и артефакты и должен объяснить разницу; тому, кто считает, окупится ли свой парк машин.
> **Когда НЕ надо.** Кэш не ускоряет плохой конвейер: если минуты уходят на лишние рёбра графа, кэш сдвинет число на проценты ([`PIPELINE_MODEL.md` §3](PIPELINE_MODEL.md)).

**Границы.** Кто исполняет задание и почему оно пустое — [`RUNNERS.md` §1–§3](RUNNERS.md). Эфемерность как допущение модели — [`PIPELINE_GUARANTEES.md` §1](PIPELINE_GUARANTEES.md). Кэш слоёв образа — [`IMAGE_BUILD_IN_CI.md` §3](IMAGE_BUILD_IN_CI.md).

---

## 1. Кэш: ключ как утверждение, промах, отравление

26 секунд холодного `~/.m2` платятся каждым прогоном. Вопрос не «как включить кэш», а «под каким ключом»: наивный `payments-m2` даёт попадание сто процентов, но ключ, не зависящий ни от чего, — не кэш, а общий изменяемый каталог. Ломается корректность — видно это из момента записи:

> «When `key` matches an existing cache, it's called a cache hit… When `key` doesn't match an existing cache, it's called a cache miss, and a new cache is automatically created if the job completes successfully.»

Запись — следствие промаха: при вечном совпадении его не будет никогда, содержимое останется таким же, как у прогона полугодовой давности — новая зависимость в `pom.xml` докачивается каждый раз и в кэш не попадает. Кэш есть, попадание есть, экономии нет.

**Ключ — это утверждение «данному содержимому соответствует ровно этот вход».** Конструкция — хэш файла, который вход полностью описывает: `pom.xml`, `package-lock.json`, `go.sum`. Молчание ключа о версии JDK при зависимости от неё делает утверждение ложным. А `restore-keys` — сознательный отказ от контракта: «…used for restoring **stale** cache if no cache hit occurred for `key`».

| Что кэшируется | Годится ли частичное совпадение |
|---|---|
| `~/.m2` — содержимое **аддитивно** | да: старый кэш экономит часть загрузки |
| `target/`, `node_modules` — принимается **целиком** | нет: частичное попадание собирает вчерашнее |

**Отравление кэша.** Восстановленное содержимое конвейер принимает без проверки — иначе кэш не давал бы выигрыша, а пишет в кэш то же задание, что выполняет чужой код и плагины: **целостность кэша равна целостности самого слабого задания, писавшего под этим ключом**, и держится испорченная запись до смены `pom.xml`.

> «Anyone with read access can create a pull request on a repository and access the contents of a cache. Forks of a repository can also create pull requests on the base branch and access caches on the base branch.»

Отсюда два правила: в кэш не кладут ничего чувствительного, и не восстанавливают в публикующее задание кэш, который мог записать менее доверенный ([`SUPPLY_CHAIN_ATTACKS.md` §2](SUPPLY_CHAIN_ATTACKS.md)).

**Чего кэш не делает и что с этим делать.** Гарантии наличия: запись вытесняется — «GitHub will remove any cache entries that have not been accessed in over 7 days», и сборка обязана оставаться корректной при пустом кэше («зелено только на прогретом исполнителе» — диагноз). **Правило:** назовите вход, от которого зависит содержимое, сделайте ключ его функцией — не можете назвать вход, кэшировать нечего; проверка — «что будет, если он пуст» и «кто мог записать то, что я восстанавливаю».

## 2. Артефакт задания против кэша: разница в том, что значит «его нет»

`target/payments.jar` производит одно задание, потребляет другое, на другой машине. Наивно — передать кэшем. Поломка в ключе: чтобы взять jar именно этого прогона, ключ обязан быть уникальным (SHA коммита), но уникальный ключ гарантирует промах, промах — запись, и хранилище ничего не переиспользует. Вытесненная запись даёт пустоту либо, при `restore-keys`, **чужой jar соседнего прогона**: образ соберётся, конвейер позеленеет, в реестр уедет вчерашний код.

> «Artifacts and caching are similar because they provide the ability to store files on GitHub, but each feature offers different use cases and cannot be used interchangeably.»

«Cannot be used interchangeably» — не стилистика: различие в одном вопросе — **что означает отсутствие содержимого.**

| | Кэш конвейера | Артефакт задания |
|---|---|---|
| Чем адресуется | ключом, вычисленным из входа | именем, заданным явно в этом прогоне |
| Что значит «его нет» | прогон медленнее | прогон красный — или собран не из того |
| Кому нужен | любому заданию, которое выиграет время | конкретному заданию-потомку |
| Событие «не нашли» | штатный промах, молчит | ошибка, обязана быть громкой |

Проверка на секунду: **сотрите хранилище целиком — конвейер должен стать медленнее, но не красным.** Всё, что после этого краснеет, было артефактом. Обратная ошибка — `~/.m2` в артефактах: 68 МБ на прогон при одинаковом содержимом у всей ветки. Артефакт оправдан, когда результат **уникален для прогона**; повторяется — кэш.

**Второе назначение — доказательство: артефакт переживает конвейер** (отчёты тестов, SBOM, план инфраструктуры):

```
$ terraform plan  -var-file=dev.tfvars       →  + manifest_path = "./out/dev.json"
$ terraform apply -var-file=staging.tfvars   →  manifest_path = "./out/staging.json"
```

Без сохранённого плана `apply` считает план заново по актуальным данным: утверждали одно, применилось другое — артефакт (`plan -out`) единственная связь между ними ([`TERRAFORM_IN_PIPELINE.md` §2](TERRAFORM_IN_PIPELINE.md)).

**Правило.** Спрашивайте не «где хранить», а «что будет, если этого не окажется». «Станет медленнее» — кэш. «Получим не тот результат» — артефакт. Смешение даёт самый дорогой отказ: зелёный конвейер с неверным содержимым.

## 3. Параллелизм и матрица: что даёт граф, а что — размножение задания

`payments` собирается на Java 21, но библиотека из него нужна сервису на Java 17 — тесты гоняют на обеих версиях. Наивно — скопировать задание `test` и поменять JDK; через месяц в одну копию добавили шаг, во вторую забыли, и «на 17 зелено» перестало что-либо значить.

> «A matrix strategy lets you use variables in a single job definition to automatically create multiple job runs that are based on the combinations of the variables.» «A matrix will generate a maximum of 256 jobs per workflow run.»

«Job runs» — матрица порождает **задания**, не шаги, а граница задания есть граница машины:

- ключ кэша обязан включать параметр ячейки — иначе Java 17 восстановит содержимое, собранное на Java 21 (§1);
- имена артефактов у ячеек обязаны различаться;
- время по стене равно времени одной ячейки, **если исполнителей хватает на все** (§4);
- минуты умножаются на число ячеек ровно: граф сокращает время по стене, не сумму (§5).

Отмена соседних ячеек при отказе включена по умолчанию ([`PIPELINE_MODEL.md` §4](PIPELINE_MODEL.md)): матрица-**гейт** отменяет — важна скорость сигнала; матрица-**отчёт о совместимости** — отмену выключают, платят минутами.

**Чего матрица не делает.** Не сокращает работу и не решает «проверок стало много»: 256 заданий — это 256 в очереди, не одно большое.

**Правило.** Параллельность даёт граф, матрица — одно определение для N вариантов. Значение параметра различается — это матрица; шаги или смысл — разные задания.

## 4. Очередь и ограничение конкурентности: две разные проблемы с похожим видом

У команды три исполнителя. Утром шесть человек шлют изменения почти одновременно — тридцать заданий по две минуты. Отдельно: два пулл-реквеста доехали до раскатки на dev в одну минуту. «Добавим исполнителей» решает первое и не решает второе, а второе дороже: две одновременные раскатки в одно окружение оставляют состояние, которого не хотел никто.

Первое — арифметика: 30 × 2 / 3 = **20 минут** до ответа последнему в очереди; по закону Литтла нужно L = λ × W исполнителей, иначе очередь растёт **неограниченно**.

**Отдельный отказ, похожий на очередь, но не она.** Задание ждёт не свободной машины, а *подходящей*: «If a job doesn't have any tags, it can only run on runners that are configured to run untagged jobs.» Метка `gpu` без такого исполнителя — ожидание до таймаута при простаивающем парке.

**Механизм второй задачи другой** — не ёмкость, а смысл: группа плюс очередь к ней.

> «Use `jobs.<job_id>.concurrency` to ensure that only a single job or workflow using the same concurrency group will run at a time.»
> «Sometimes running multiple jobs or pipelines at the same time in an environment can lead to errors during the deployment. To avoid these errors, use the `resource_group` attribute.»

Добавить исполнителей значит **увеличить** конкурентность; группа — единственный способ ограничить её.

| Что делает задание | Что делать с уже идущим | Почему |
|---|---|---|
| Проверки пулл-реквеста, пришёл новый коммит | отменять | старый прогон больше ничего не утверждает |
| Раскатка в окружение | ждать, никогда не отменять | прерванная раскатка оставляет промежуточное состояние |
| Применение изменений инфраструктуры | ждать | параллельное применение меняет состояние под чужим планом |

```
Error: Saved plan is stale
The given plan file can no longer be applied because the state was changed by
another operation after the plan was created.
```

Отказ правильный: группа защищает не машину, а **предположение под изменением**.

**Правило.** Очередь лечится числом исполнителей, конкурентность — группой, и никогда наоборот. Что будет, если два изменения доедут до раскатки в одну секунду? Нет ответа — нет группы.

## 5. Экономика минут: когда свой парк на прерываемых машинах дешевле

«Перейдём на прерываемые (spot) машины — сэкономим?» Цена часа, делённая на шестьдесят, против цены минуты провайдера — неверный счёт: путает оплату **за использование** с оплатой **за владение**. Величин три; тарифы не приводятся — устаревают быстрее текста.

*Сколько минут вы покупаете.* Считать надо **сумму времени заданий, не критический путь**: у `payments` сумма 3 + 1 + 2 + 6 + 2 + 1 = **15 задание-минут** при пути 12 минут. Параллельность и матрица (§3) сокращают время по стене и **не сокращают счёт вовсе**. При 24 прогонах в день — 360 задание-минут в сутки, около **7 500 в месяц**.

*Загрузка парка.* В месяце 43 200 минут: постоянно включённая машина загружена на 7 500 / 43 200 ≈ **17 %**. Парк размеряется по **пику** (§4): утренний всплеск в три машины — каждая загружена ещё втрое меньше.

*Точка равновесия.* Свой парк выгоден при `p_управляемая > p_владения / U`. При U ≈ 0,17 своя минута должна быть дешевле управляемой **в шесть раз**, чтобы выйти в ноль.

**Прерываемые машины снижают `p_владения`, добавляя два слагаемых:**

- **Холодный старт амортизируется длиной задания.** Минута подъёма — это +50 % для двухминутного задания и +5 % для двадцатиминутного.
- **Прерывание — повторный прогон.** При вероятности p ожидаемое число прогонов 1 / (1 − p): p = 0,1 даёт 1,11, то есть +11 % к минутам, и часть прогонов краснеет без связи с кодом — неотличимо от ненадёжного теста.

**Постоянное слагаемое не сокращается объёмом**: образ исполнителя, обновление ОС, зависшие машины — часы человека, одни и те же при 500 и 50 000 минутах.

**Правило.** Ответ не «сэкономим или нет», а «начиная с какого объёма»: выгода растёт линейно, накладные расходы постоянны — порог есть всегда. Нужны три числа: задание-минуты в месяц, пиковая конкурентность, часы человека. Сократить работу почти всегда дешевле удешевления минуты.

## 6. Шпаргалка

| Вопрос | Ответ одной строкой |
|---|---|
| Что такое ключ кэша | утверждение «этому содержимому соответствует ровно этот вход» |
| Когда происходит запись в кэш | только на промахе: вечный ключ означает вечно первое содержимое |
| Когда `restore-keys` уместен | когда содержимое аддитивно (`~/.m2`); опасен там, где берётся целиком |
| Чему равна целостность кэша | целостности самого слабого задания, писавшего под этим ключом |
| Кэш или артефакт | сотрите хранилище: стало медленнее — кэш, стало красно — артефакт |
| Что даёт параллельность | граф; матрица даёт одно определение для N вариантов и умножает счёт на N |
| Чем лечится очередь и чем конкурентность | первое ёмкостью, второе именованной группой, и никогда наоборот |
| Отменять идущий прогон или ждать | проверки — отменять, раскатку и применение инфраструктуры — ждать |
| Задание ждёт при простаивающем парке | это не очередь, а несовпадение меток |
| Когда свой парк дешевле | когда `p_управляемая > p_владения / загрузка`; платят за сумму задание-минут |

### Формулировки для собеседования

- «Ключ кэша — утверждение о входе, а `restore-keys` — сознательный отказ от него ради скорости.»
- «Кэш и артефакт различаются не хранилищем, а тем, что означает их отсутствие: медленнее против неверно.»
- «Матрица не ускоряет: параллельность даёт граф, а матрица — одно определение для N вариантов, умножающее счёт на N.»
- «Очередь лечится ёмкостью, конкурентность — именованной группой; добавить исполнителей — увеличить конкурентность, не ограничить её.»
