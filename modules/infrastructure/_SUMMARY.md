# Infrastructure — Semantic Summary

## Core Model
Путь в эксплуатацию: **упаковка** (контейнер убирает окружение из числа переменных) →
**оркестрация** (Kubernetes приводит фактическое состояние к желаемому) → **упаковка релиза**
(Helm отделяет структуру от значений) → **наблюдаемость** → **эксплуатационный контекст**
(секреты, облако). Каждый слой — размен: контейнер даёт воспроизводимость и отбирает границу
безопасности; Kubernetes даёт самовосстановление и добавляет способов сломаться; облако даёт
эластичность и берёт плату за право не угадывать заранее. Сквозной пример модуля: Orders API —
Spring Boot backend и nginx-frontend, три экземпляра, 200 запросов в секунду, p99 ≤ 300 мс,
управляемый PostgreSQL, пароль в Vault.

## Key Concepts
- **Контейнер**: namespaces (видимость) + cgroups (ресурсы); образ — слоистая ФС (copy-on-write),
  кэш слоёв задаётся порядком инструкций; multi-stage; OCI, containerd/runc; distroless; PID 1.
- **Kubernetes**: цикл согласования; управляющий слой (apiserver, etcd, планировщик, контроллеры)
  и слой нагрузки (kubelet, kube-proxy); под и pause-контейнер; Deployment/StatefulSet/DaemonSet/Job;
  Service, Ingress, Gateway API; пробы liveness/readiness/startup; requests, limits, классы QoS;
  HPA/VPA/CA; RBAC, NetworkPolicy; PV/PVC/CSI; разнос по узлам и зонам.
- **Helm**: чарт = шаблоны + значения; релиз = именованный экземпляр с историей ревизий в кластере;
  `helm rollback`; hooks; sub-charts; альтернативы — Kustomize, Argo CD; в CI `--atomic --wait`.
- **Наблюдаемость**: три столпа и разная цена хранения; SLI/SLO/SLA; бюджет ошибок = 1 − SLO;
  трасса как граф отрезков; W3C Trace Context, OpenTelemetry; выборка по голове и по хвосту;
  exemplars; wide events.
- **Метрики**: Counter (`rate`), Gauge (снимок), Histogram (корзины, `histogram_quantile`),
  Summary (квантиль на клиенте, не агрегируется); модель опроса; PromQL; Micrometer; правила
  предвычисления и оповещения; RED/USE/Four Golden Signals; долгое хранение — Thanos, Mimir.
- **Журналирование**: структурированный JSON; уровни по критерию «можно ли написать алерт»;
  MDC в `ThreadLocal`; сквозной идентификатор; stdout в контейнере; ELK против Loki; асинхронный
  appender; ленивое форматирование.
- **Секреты**: конвертное шифрование (KEK + DEK); задача первого секрета: роль IAM → токен
  ServiceAccount → AppRole; Vault (распечатывание, динамические секреты); состояние Terraform;
  ESO, Sealed Secrets, SOPS; mTLS.
- **Облако**: регион и зона доступности (домен отказа); IaaS/PaaS/SaaS/FaaS; HA против DR;
  RPO и RTO; своя база против управляемой; IaC (состояние, блокировка, расхождение); привязка
  к поставщику; скрытые статьи счёта.

## Important Invariants
- Контейнеры делят ядро с хостом: изоляция ресурсов, а не граница доверия. Слои образа
  неизменяемы, записываемый слой живёт ровно столько, сколько контейнер.
- Изменение слоя аннулирует все последующие: 2.64 с против 0.39 с на модельной сборке (измерено).
- Класс QoS **выводится** из соотношения requests и limits, а не задаётся: `requests == limits` →
  Guaranteed, `requests < limits` → Burstable, ничего → BestEffort (проверено в кластере).
- Лимит по памяти становится cgroup-лимитом того же значения и при превышении **убивает**
  контейнер (`reason: OOMKilled`); лимит по процессору троттлит.
- Liveness проверяет только жизнь процесса: зависимость в ней превращает чужой отказ
  в перезапуск всех подов сразу.
- `:latest` даёт недетерминированную выкатку при неизменном манифесте.
- Percentile не аддитивен: складывают корзины гистограммы, а не percentile экземпляров.
- `rate()` определён только для Counter; мощности меток перемножаются, поэтому метка с
  идентификатором объекта убивает Prometheus.
- Kubernetes Secret — это base64: право `get secret` равносильно знанию пароля (проверено).
- Бюджет ошибок при SLO 99.9% — 43 мин 12 с за 30 дней; период надо называть явно.
- Зона доступности — отдельный домен отказа: три экземпляра в одной зоне не надёжнее одного.
- MDC живёт в `ThreadLocal` и сам в пул потоков не переезжает.

## Common Pitfalls
- `COPY . .` перед установкой зависимостей — кэш сборки аннулируется при каждой правке кода.
- Запуск от root и отсутствие `--cap-drop=ALL`: по умолчанию контейнер получает 14 capabilities,
  включая `cap_setuid` и `cap_dac_override`.
- Один эндпоинт на liveness и readiness → цикл перезапусков под нагрузкой.
- Лимиты на процессор при всплесковой нагрузке → троттлинг при свободном процессоре.
- Секрет в переменной окружения → виден в `docker inspect`, `/proc/<pid>/environ`, дампах.
- Секрет в `values.yaml` → в git, в журналах CI и в `helm get values`.
- Чужой чарт без закреплённой версии → несовместимые изменения приезжают молча.
- Персональные данные и учётные данные в журнале → нарушение GDPR, PCI-DSS, HIPAA.
- Terraform без блокировки состояния → два одновременных применения расходятся с реальностью.
- Оптимизация счёта с крупнейшей строки вместо скрытых статей (исходящий трафик, NAT, трафик
  между зонами).
