# Ex04 — Уровни согласованности

## Условие

Маркетплейс работает в двух дата-центрах: `dc_eu` (основной трафик) и `dc_us`.
Требования бизнеса:

- **Оформление заказа** — потеря подтверждённого заказа недопустима; задержка до 150 мс приемлема.
- **Лента «мои заказы»** — допускается отставание в несколько секунд; задержка критична.
- **Смена адреса доставки** — пользователь обязан увидеть собственное изменение сразу
  после сохранения.
- **Резерв последнего экземпляра товара** — двое не должны зарезервировать один экземпляр.

Кластер обязан обслуживать чтение при полной потере одного дата-центра.

## Задание

В `schema.cql` определи keyspace с фактором репликации по дата-центрам, а в `decisions.md` —
уровень согласованности для каждого из четырёх сценариев с обоснованием.

## Критерии приёмки

- [ ] Для каждого сценария назван уровень согласованности **чтения и записи** отдельно.
- [ ] Показано арифметически, выполняется ли `R + W > N` и что это даёт в каждом случае.
- [ ] Обосновано, почему не `QUORUM` там, где выбран `LOCAL_QUORUM` (и наоборот).
- [ ] Для резерва экземпляра объяснено, почему обычной записи недостаточно, и названа цена
      выбранного механизма в раундах обмена.
- [ ] Сказано, что произойдёт с каждым сценарием при полной потере `dc_us`.

## Проверка

```bash
docker exec -i cass cqlsh < schema.cql
docker exec cass cqlsh -e "CONSISTENCY LOCAL_QUORUM; SELECT ...;"
```
