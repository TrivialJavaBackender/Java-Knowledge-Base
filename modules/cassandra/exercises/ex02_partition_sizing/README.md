# Ex02 — Размер партиции

## Условие

Коллега принёс на ревью таблицу отчёта по продавцу:

```cql
CREATE TABLE orders_by_seller (
    seller_id   uuid,
    created_at  timestamp,
    order_id    uuid,
    total_amount decimal,
    status      text,
    PRIMARY KEY (seller_id, created_at, order_id)
) WITH CLUSTERING ORDER BY (created_at DESC);
```

На тестовых данных всё работает. Крупнейший продавец маркетплейса оформляет 500 заказов в сутки
и работает третий год; данные хранятся бессрочно.

## Задание

1. Посчитай, сколько строк и сколько байт окажется в партиции крупнейшего продавца через год
   и через три года. Расчёт запиши в `analysis.md` — с исходными числами, а не «много».
2. Назови, что именно сломается первым и на каком этапе (запись, чтение, ремонт, компактизация).
3. Предложи исправленную схему в `schema.cql` и покажи, как изменится запрос «заказы продавца
   за календарный день» и «заказы продавца за произвольный период в 30 дней».

## Критерии приёмки

- [ ] Расчёт содержит: число строк, оценку байт на строку, итог по партиции.
- [ ] Названа граница, после которой партиция считается проблемной, и источник этой границы.
- [ ] Исправление не ломает запрос за период: показано, сколько партиций читает клиент
      и почему это приемлемо.
- [ ] Объяснено, почему выбранный размер бакета именно такой, а не в десять раз больше или меньше.
