# Cassandra — Summary

## Core Model

Wide-column store из линии Dynamo и BigTable: модель данных и хранение от BigTable, распределение
и отказоустойчивость от Dynamo. Ведущего узла нет — запрос принимает любой узел и становится
координатором на время этого запроса. Единица размещения и атомарности — партиция: ключ партиции
хешируется целиком и определяет владельцев, ключ кластеризации задаёт порядок строк внутри
партиции на диске.

Запись не читает: мутация дописывается в commitlog и кладётся в memtable, SSTable появляется
позже при сбросе. Чтение зависит от числа мест, где ключ может лежать, и заканчивается слиянием
источников. Отсюда асимметрия: дешёвая запись, дорогое чтение.

Сквозной пример модуля — история заказов маркетплейса: 50 млн пользователей, пик 20 тыс. записей
в секунду, три запроса (заказы пользователя, заказ по идентификатору, заказы продавца за период),
два дата-центра.

## Key Concepts

- **Моделирование от запросов.** Сначала список запросов, потом таблицы: таблица на запрос,
  денормализация вместо соединений. `JOIN` отсутствует в грамматике CQL.
- **Настраиваемая согласованность.** Уровень задаётся на запрос; `N` для `QUORUM` — сумма
  факторов репликации по всем дата-центрам, поэтому в мультирегионе рабочий выбор `LOCAL_QUORUM`.
- **Стратегии уплотнения.** STCS собирает файлы по размеру, LCS держит уровни, TWCS не смешивает
  временные окна, UCS в 5.0 параметризует всё это одним механизмом.
- **Tombstone.** Удаление — это запись маркера. Маркер живёт минимум `gc_grace_seconds` и
  читается наравне с живыми строками.
- **Кольцо токенов и vnodes.** Узел владеет многими диапазонами вразброс, поэтому ввод и вывод
  узла размазывают передачу данных по кластеру.
- **Драйвер как часть механизма.** Маршрутизация по токену работает только у подготовленного
  запроса со всеми связанными компонентами ключа партиции.

## Important Invariants

- Атомарность и изоляция существуют **только в границах одной партиции**. Между партициями нет
  ни двухфазного коммита, ни отката.
- Метка времени лежит на **ячейке**, а не на строке: строка после схождения собирается из
  кусочков разных записей.
- Маркер удаления выбрасывается только при **двойном** условии: срок истёк и данных под ним нет
  ни в одном файле за пределами прохода уплотнения.
- Имя дата-центра для `NetworkTopologyStrategy` даёт **снитч**, а не файл конфигурации и не CQL.
- `ALTER KEYSPACE` при добавлении дата-центра меняет только описание репликации; данные двигает
  отдельный `nodetool rebuild`.
- Таймаут драйвера **не отменяет** запрос на сервере: мутация могла примениться.

## Common Pitfalls

- **Неограниченная партиция.** Ключ без временного бакета растёт линейно и вечно; партиция
  читается и уплотняется целиком.
- **`ALLOW FILTERING` как «просто разрешение».** Это не план: при наличии индекса будет индекс,
  без него — скан. Разницу показывает только трассировка.
- **2i на колонке низкой кардинальности.** Скрытая таблица, где ключ партиции равен значению:
  пять статусов дают пять партиций, растущих с объёмом данных узла.
- **Cassandra как очередь.** Постоянное удаление обработанных записей превращает чтение головы
  в сканирование маркеров.
- **`BATCH` ради экономии обращений.** Атомарность и изоляция только внутри партиции, а
  межпартиционный batch делает координатор узким местом.
- **Guardrails по умолчанию выключены**, а порог tombstone на чтении не имеет отношения к порогу
  на записи.
- **Счётчики не идемпотентны:** повтор по таймауту добавляет ещё одну дельту.
