# Шпаргалка: 15 минут до собеседования

> **Какую проблему решает.** Собирает всё, что можно забыть от волнения, в таблицы, которые
> просматриваются за один заход.
> **Кому это надо.** Тому, кто уже прошёл теорию и повторяет перед собеседованием.
> **Когда НЕ надо.** Как учебный материал: без остальных файлов это набор фактов без объяснений.

## Билдеры

| | Возвращает | Приостанавливает вызывающего | Ошибка |
|---|---|---|---|
| `launch` | `Job` | нет | летит вверх сразу |
| `async` | `Deferred<T>` | нет | хранится до `await()` (но родителя всё равно отменит, если не supervisor) |
| `withContext` | значение | да | бросается из блока |
| `runBlocking` | значение | **блокирует поток** | бросается вызывающему |
| `coroutineScope` | значение | да | ошибка ребёнка → ошибка блока |
| `supervisorScope` | значение | да | ошибки прямых детей независимы |
| `produce` | `ReceiveChannel<T>` | нет | через `close(cause)` |
| `flow { }` | `Flow<T>` | нет (ленивый) | у коллектора |

**Правило:** нет параллелизма → `withContext`, а не `async {}.await()`.
→ [`BASICS.md`](BASICS.md)

## `CoroutineStart`

| Режим | Поведение | Зачем |
|---|---|---|
| `DEFAULT` | планируется сразу | обычный случай |
| `LAZY` | стартует по `start()`/`join()`/`await()` | подготовить, запустить по условию |
| `ATOMIC` | нельзя отменить до первой приостановки | захват ресурса в начале блока |
| `UNDISPATCHED` | начало — синхронно в текущем потоке | подписаться до возврата управления |

## `Job`

| Состояние | `isActive` | `isCompleted` | `isCancelled` |
|---|---|---|---|
| New (LAZY) | false | false | false |
| Active | **true** | false | false |
| Completing (ждёт детей) | true | false | false |
| Cancelling | false | false | **true** |
| Cancelled | false | **true** | **true** |
| Completed | false | **true** | false |

`Job()` — падение ребёнка убивает родителя. `SupervisorJob()` — не убивает, но **только для прямых детей**.
`join()` не бросает, `await()` бросает.
→ [`BASICS.md`](BASICS.md), [`STRUCTURED_CONCURRENCY.md`](STRUCTURED_CONCURRENCY.md)

## Отмена — 7 правил

1. Отмена кооперативна: `cancel()` только помечает `Job` и бросает `CancellationException` в точках приостановки.
2. CPU-цикл сам не отменится → `ensureActive()` / `isActive` / `yield()`.
3. Блокирующий вызов сам не отменится → `runInterruptible { }`.
4. `CancellationException` никогда не глотать: `catch (e: CancellationException) { throw e }`.
5. `runCatching` вокруг suspend — баг: он ловит отмену.
6. suspend-очистка в `finally` → `withContext(NonCancellable) { }`.
7. Ждать завершения — `cancelAndJoin()`, а не `cancel()`.

→ [`CANCELLATION_EXCEPTIONS.md`](CANCELLATION_EXCEPTIONS.md)

## Исключения — 6 правил

1. `try/catch` вокруг `launch` не ловит ничего.
2. `CoroutineExceptionHandler` — только для корневых корутин scope; для `async` и дочерних не работает.
3. `coroutineScope` пробрасывает ошибку ребёнка → её можно ловить `try/catch` вокруг блока.
4. `supervisorScope` — падение прямого ребёнка не трогает соседей (но не внуков).
5. Первое исключение — основное, остальные в `suppressed`.
6. Обрабатывай на границе операции (там, где создан scope).

→ [`CANCELLATION_EXCEPTIONS.md`](CANCELLATION_EXCEPTIONS.md)

## Диспетчеры

| | Потоков | Для чего |
|---|---|---|
| `Default` | = ядрам | CPU |
| `IO` | до 64, общий пул с `Default` | блокирующий ввод-вывод |
| `Unconfined` | какой попадётся | тесты, редкие оптимизации |
| `limitedParallelism(n)` | без новых потоков | лимит под пул БД / внешний API |
| `limitedParallelism(1)` | — | confinement вместо `Mutex` |
| `Executors.newVirtualThreadPerTaskExecutor().asCoroutineDispatcher()` | виртуальные | дешёвая блокировка (JDK 21) |

Блокирующий код на `Default` = голодание пула. Диспетчер всегда инжектируй параметром — иначе не тестируется.
→ [`DISPATCHERS.md`](DISPATCHERS.md)

## Синхронизация

| Нужно | Инструмент |
|---|---|
| счётчик | `AtomicInteger` |
| критическая секция с suspend | `Mutex.withLock` (**не реентерабельный**) |
| лимит параллелизма | `Semaphore.withPermit` |
| изоляция состояния | `limitedParallelism(1)` / актор на `Channel` |
| состояние компонента | `MutableStateFlow` + `update { }` |

`synchronized` вокруг suspend — нельзя: монитор принадлежит потоку.
→ [`SHARED_STATE.md`](SHARED_STATE.md)

## Cold vs Hot

| | Тип | Кому достаётся значение | Завершается |
|---|---|---|---|
| `Flow` | холодный | каждому свой запуск | да |
| `SharedFlow` | горячий | всем подписчикам | нет |
| `StateFlow` | горячий | всем, только последнее | нет |
| `Channel` | горячий | ровно одному | по `close()` |

Событие → `SharedFlow`/`Channel`. Состояние → `StateFlow`. Поток данных с преобразованиями → `Flow`.
→ [`FLOW.md`](FLOW.md), [`FLOW_ADVANCED.md`](FLOW_ADVANCED.md), [`CHANNELS.md`](CHANNELS.md)

## flatMap-семейство

| | Предыдущий внутренний поток | Порядок | Для чего |
|---|---|---|---|
| `flatMapConcat` | дожидается | строгий | последовательная обработка |
| `flatMapMerge(n)` | параллельно, до n | не гарантирован | параллельная обработка с лимитом |
| `flatMapLatest` | **отменяет** | последний побеждает | поиск, «текущее» значение |

## Обратное давление

| Оператор | Что делает | Что теряем |
|---|---|---|
| — | продюсер ждёт коллектора | ничего, медленно |
| `buffer(n)` | продюсер работает вперёд | ничего, пока буфер не полон |
| `buffer(n, DROP_OLDEST)` | буфер не переполняется | старые элементы |
| `conflate` | только последнее | все промежуточные |
| `collectLatest` | отменяет обработку | незаконченную работу |

## Время

| Оператор | Поведение |
|---|---|
| `debounce(t)` | эмитит после паузы `t` (поиск по вводу) |
| `sample(t)` | последнее значение раз в `t` (метрики) |

| | Старт апстрима | Остановка |
|---|---|---|
| `Eagerly` | сразу | никогда |

## Интероп

| Что есть | Инструмент |
|---|---|
| колбек | `suspendCancellableCoroutine` + `invokeOnCancellation` |

| suspend → Java | `scope.future { }` |

## Дерево решений

- **Несколько независимых вызовов** → `coroutineScope { async … }` + `awaitAll`.
- **Много вызовов, нужен лимит** → `Semaphore` / `flatMapMerge(n)` / `limitedParallelism(n)`.
- **Нужен первый успешный** → `select { onAwait }` либо `async` + отмена проигравших.
- **Частичная деградация** → `supervisorScope` + `Result` (с пробросом `CancellationException`).
- **Одинаковые запросы одновременно** → single-flight: `Mutex` + `CompletableDeferred`.
- **Поток событий от колбек-API** → `callbackFlow` + `awaitClose`.
- **Один дорогой источник, много подписчиков** → `shareIn(scope, WhileSubscribed(5000), replay = 1)`.
- **Состояние компонента** → `MutableStateFlow` + `update { }`.
- **Очередь задач с воркерами** → `Channel` + fan-out на N корутин.
- **Остановить сервис** → перестать принимать → `join` с таймаутом → `cancelAndJoin`.

→ [`BACKEND_PATTERNS.md`](BACKEND_PATTERNS.md)

## Формулировки, которые хорошо звучат

1. «Корутина — это не лёгкий поток, а колбек, который написал компилятор: `suspend`-функция получает скрытый `Continuation` и возвращает либо значение, либо `COROUTINE_SUSPENDED`».
2. «Приостановка — это обычный `return` из обычного метода; поток освобождается, состояние остаётся в объекте на куче».
3. «Возобновляет тот, у кого появился результат: таймер, другая корутина, поток HTTP-клиента. Диспетчер решает не кто, а где».
4. «Структурная конкурентность гарантирует, что родитель дождётся детей, а отмена и ошибки пойдут по дереву — поэтому нет утечек фоновых задач».
5. «Отмена кооперативна: библиотека может только сообщить в точке приостановки, дальше — ответственность кода».
6. «`CancellationException` — штатный сигнал, а не ошибка; глотать её нельзя, иначе корутина переживёт отмену».
7. «`launch` бросает исключение сразу, `async` хранит его в `Deferred` до `await`».
8. «`CoroutineExceptionHandler` — это последний рубеж корневой корутины, а не `try/catch`».
9. «Блокирующий вызов на `Default` отбирает ядро у всей программы, поэтому он уезжает на IO или на выделенный диспетчер».
10. «`limitedParallelism` даёт лимит без новых потоков — им удобно согласовывать конкурентность с пулом соединений».
11. «Flow холодный: продюсер стартует на каждый `collect`; если апстрим дорогой — `shareIn`».
12. «`catch` видит только апстрим; ошибки коллектора туда не попадают».
13. «`take` останавливает апстрим служебным `AbortFlowException` — поэтому нельзя ловить `Throwable` вокруг `emit`».
14. «`StateFlow` конфлейтит и сравнивает по `equals`, поэтому для событий он не годится».
15. «Параллельность в тесте проверяется виртуальным временем: `currentTime` должен быть равен максимуму, а не сумме».
