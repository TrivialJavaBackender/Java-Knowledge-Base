# Microservices — Semantic Summary

## Core Model
Микросервисы — это **размен**: покупается независимое развёртывание, автономия команд, изоляция
отказа и независимое масштабирование; платится тем, что вызов метода становится сетевым (~10 нс →
~95 мкс, ×9000), появляется третий исход «неизвестно», доступность цепочки перемножается, а общая
транзакция исчезает. Размен окупается, когда цена координации между командами превысила цену
распределённости, — то есть решение экономическое, а не техническое. Сквозной пример модуля:
оформление заказа, `Checkout → Order → Payment → Inventory → Notification`, 500 rps, внешний
провайдер с p50 300 мс.

## Key Concepts
- **Границы**: три критерия разреза (бизнес-возможность, скорость изменения, владение данными);
  Strangler Fig; извлечение сервиса — сначала код, потом данные.
- **Синхронная связь**: бюджет таймаутов, крайний срок против таймаута, gRPC (IDL, трейлер со
  статусом, health checking), пул соединений по закону Литтла, L4 против HTTP/2.
- **Изоляция отказа**: каскад через `L = λ × W`; предохранитель (доля в окне, не «подряд»);
  переборка; деградация по критерию «какое знание потеряно».
- **Асинхронная связь**: команда/событие/документ; хореография против оркестрации; «хотя бы один
  раз» + идемпотентность потребителя; четыре условия порядка; очередь против журнала.
- **Данные**: база на сервис (запрет действует и на чтение); композиция через API; материализованное
  представление; источник истины на поле, а не на таблице.
- **Согласованность**: 2PC и его блокирующая природа; сага с компенсациями; семантическая
  блокировка; двойная запись ломается в обоих порядках → Outbox; CDC как альтернатива.
- **CQRS/ES**: разделение моделей, а не хранилищ; проекция и её отставание; журнал как источник
  истины; снапшоты; апкастинг.
- **Контракты**: обратная и прямая совместимость; tolerant reader; версионирование; компонентный
  тест против контрактного.
- **Инфраструктурный слой**: три места для сквозной функциональности (библиотека / sidecar / шлюз);
  API Gateway против BFF; обнаружение сервисов; service mesh, xDS, ambient.
- **Доверие**: SPIFFE ID и SVID; аттестация узла и нагрузки; обмен токена (RFC 8693); делегирование
  против олицетворения; где авторизация.

## Important Invariants
- Доступность синхронной цепочки — произведение доступностей звеньев; убрать звено дешевле, чем
  добавить всем девятку.
- Идемпотентность обязана быть на принимающей стороне: повторяющий не знает, выполнилась ли операция.
- «Ровно один раз» между системами не существует. Outbox даёт атомарность факта и намерения плюс
  доставку не меньше одного раза; получатель обязан дедуплицировать.
- Компенсация — новая бизнес-операция, а не откат: идемпотентна, повторяема, не вправе отказать по
  бизнес-причине.
- Медленная зависимость опаснее упавшей: упавшая отвечает мгновенно, медленная удерживает конечный
  ресурс.
- Схема становится контрактом в момент, когда на неё кто-то полагается, — включая читателей.
- Аутентификацию можно централизовать на краю, тонкую авторизацию — нельзя: она зависит от
  актуального состояния конкретной записи.

## Common Pitfalls
Распределённый монолит (уплачено всё, куплено ничего); наносервисы; общая база; сущностные сервисы
(`UserService`/`OrderService`); синхронная цепочка на весь запрос; сага там, где хватило бы
агрегата; общая доменная библиотека как скрытая связность; окружение на сорок сервисов. Ходовые
неверные формулировки: «предохранитель размыкается после N ошибок подряд» (механизма «подряд» нет),
«Outbox даёт exactly-once», «Event Sourcing даёт аудит бесплатно», «SVID обязан быть короткоживущим
по спецификации», «включили транзакции Kafka — потребитель не увидит откаченное»
(`isolation.level` по умолчанию `read_uncommitted`).

## Related Modules
- **ddd** — Bounded Context и Context Map как способ найти границы; агрегат как граница транзакции;
  доменная рамка Outbox/Saga/CQRS.
- **system-design** — Kafka, каталог политик надёжности (повторы, джиттер, сброс нагрузки, DLQ),
  HTTP/2 и TLS, OAuth2/OIDC как протоколы, обратный прокси и балансировщик.
- **databases** — шардинг, репликация, CDC со стороны базы, локальные транзакции.
- **infrastructure** — Kubernetes (Service, CoreDNS, probes), наблюдаемость и трассировка, mTLS и
  секреты.
- **software-engineering** — пирамида тестов, Pact, TestContainers.
- **engineering-process** — релизные стратегии, канареечная раскатка, feature flags, expand/contract.
- **concurrency** — закон Литтла, размер пула, цена потока.
