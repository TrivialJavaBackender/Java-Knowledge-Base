# Go — Основы синтаксиса

> Структура программы, переменные и нулевые значения, константы и `iota`, базовые типы,
> управление потоком (`for`/`if`/`switch`), функции (множественный возврат, variadic),
> видимость по заглавной букве.
> Это фундамент — на нём держатся [типы и методы](./TYPES_STRUCTS_METHODS.md) и всё остальное.

Аудитория — разработчик из Java/Kotlin, видящий Go впервые. Там, где помогает, даются параллели.
Главное отличие в духе языка: Go намеренно маленький. Нет наследования классов, нет исключений,
нет перегрузки операторов, нет неявных преобразований, нет тернарного оператора, один цикл.
То, что в Java решается богатством синтаксиса, в Go решается явностью и компилятором.

## 1. Структура программы

### Пакеты

Единица компиляции в Go — **пакет** (package), а не файл и не класс. Пакет — это директория:
все `.go`-файлы в одной директории обязаны объявлять один и тот же `package`. Имя пакета по
соглашению совпадает с именем директории (но формально это независимые вещи).

```go
package main   // первая значащая строка КАЖДОГО .go-файла

import "fmt"

func main() {
    fmt.Println("Привет, Go")
}
```

Параллель с Java: пакет в Go ближе к Java-пакету по роли (пространство имён + граница
видимости), но **без иерархии**. Пакеты `net/http` и `net/url` не «вложены» друг в друга —
это просто пути; `http` ничего не наследует от `net`. Импортируется всегда пакет целиком,
выборочного импорта отдельных символов (как `import java.util.List`) нет.

### `package main` и точка входа

Пакет с именем `main` — особый: компилятор делает из него **исполняемый файл**. В нём должна
быть функция `func main()` — без аргументов и без возвращаемого значения. Любой другой пакет —
это библиотека, у неё нет `main`, она только импортируется.

```go
func main() { /* точка входа; аргументы — через os.Args, код выхода — через os.Exit */ }
```

Аргументов у `main` нет (в отличие от `String[] args` в Java). Аргументы командной строки
лежат в `os.Args []string`, переменные окружения — в `os.Getenv`, код возврата задаётся
через `os.Exit(code)` (по умолчанию 0).

### `import`: группировка, алиасы, blank

Импорты идут блоком в начале файла. Идиоматичная форма — скобочная группа (`gofmt`
отсортирует пути по алфавиту):

```go
import (
    "errors"
    "fmt"
    "strings"

    "github.com/google/uuid"   // сторонние — отдельной группой, gofmt не сортирует между группами
)
```

Обращение всегда по **имени пакета** (последний сегмент пути), а не по полному пути:
`strings.ToUpper`, а не `"strings".ToUpper`. Это как статический импорт класса в Java,
только обязательный — голого `ToUpper()` без префикса не бывает.

Два специальных модификатора импорта:

```go
import (
    mrand "math/rand"   // алиас: обращаемся как mrand.Intn — решает конфликт имён
    _     "image/png"   // blank-импорт: пакет не используется напрямую, нужен ради side-effect init()
)
```

- **Алиас** даёт пакету другое локальное имя. Нужен, когда два импорта дают одинаковое имя
  пакета (`math/rand` и `crypto/rand` — оба `rand`).
- **Blank `_`** импортирует пакет **только ради побочного эффекта** его `init()`-функций
  (например, регистрация драйвера базы данных или декодера изображения). Без `_` такой импорт
  был бы ошибкой «imported and not used».

## 2. Переменные

### `var`, `:=` и нулевые значения

Объявить переменную можно двумя способами.

```go
var count int = 10     // полная форма: имя, тип, значение
var name = "Pavel"     // тип выводится из значения (int/string/...)
var done bool          // БЕЗ инициализатора — получает zero value (здесь false)

total := 0             // краткая форма := — объявление + вывод типа, ТОЛЬКО внутри функций
```

Главная идея, отличающая Go от Java: **нулевое значение (zero value)**. В Go нет
«неинициализированных» переменных. Если не задать значение, переменная гарантированно получает
нулевое значение своего типа, и это не мусор, а часть контракта языка:

| Тип | Zero value |
|-----|-----------|
| `int`, `int64`, `uint`, ... | `0` |
| `float64`, `float32` | `0` |
| `bool` | `false` |
| `string` | `""` (пустая строка, **не** `nil`) |
| указатель, `slice`, `map`, `chan`, `func`, интерфейс | `nil` |
| `struct` | структура, каждое поле которой = свой zero value |

Сравните с Java: там локальная переменная без инициализации — **ошибка компиляции**
(`variable might not have been initialized`), а поле класса молча получает `0`/`null`.
В Go правило единое для всех переменных, и язык спроектирован так, чтобы **zero value было
полезным**: `var buf bytes.Buffer` сразу готов к записи, `var mu sync.Mutex` сразу можно
блокировать, `var s []int` — корректный пустой слайс, в который можно `append`. Это называют
«make the zero value useful» — важный принцип дизайна API в Go.

`:=` против `var`:

- `:=` работает **только внутри функций** (на уровне пакета — лишь `var`/`const`).
- `:=` требует, чтобы **хотя бы одна** переменная слева была новой; остальные могут уже
  существовать (тогда им просто присваивается значение).
- Если нужен явный тип или нулевое значение без инициализатора — нужен `var`.

```go
func read() {
    f, err := open("a")     // обе новые
    g, err := open("b")     // g новая, err переиспользуется — ОК (одна новая слева)
    var timeout time.Duration   // хотим zero value (0) и явный тип — нужен var
    _ = f; _ = g; _ = timeout
}
```

### Групповое объявление

`var` и `const` можно группировать скобками — читается как таблица:

```go
var (
    host    = "localhost"
    port    = 8080
    verbose bool          // zero value false
)
```

### Неиспользуемые переменные и импорты = ошибка компиляции

Это шокирует приходящих из Java: **неиспользуемая локальная переменная и неиспользуемый
импорт — не warning, а ошибка**, программа не компилируется.

```go
func f() {
    x := compute()   // ❌ "declared and not used", если x нигде не читается
}
```

Зачем так жёстко: мёртвый код и забытые импорты — источник путаницы и багов (особенно
импорт «не того» пакета). Go выбирает чистоту компиляции ценой строгости. Лазейка — **blank
identifier** `_`: ему можно присвоить что угодно, и это «использование» не считается.

```go
_, err := strconv.Atoi(s)   // значение не нужно — отбрасываем в _
result, _ := compute()      // ошибку сознательно игнорируем (обычно так делать не стоит)
```

Заметьте: на **поля пакета** (package-level `var`) правило неиспользования **не
распространяется** — только на локальные переменные.

## 3. Константы

`const` — значение, известное на этапе компиляции. Константы бывают только базовых типов
(числа, строки, `bool`); слайс или результат вызова функции константой быть не может.

```go
const Pi = 3.14159
const Greeting = "hello"

const (
    StatusOK       = 200
    StatusNotFound = 404
)
```

Особенность Go — **нетипизированные константы** (untyped constants). Литерал `3.14` или
константа без явного типа не имеет типа до момента использования и обладает «произвольной
точностью». Это позволяет писать так, что в Java потребовало бы явных кастов:

```go
const big = 1 << 40       // нетипизированная, влезает в любой достаточно широкий тип
var x float64 = big       // ок, конвертируется в float64 при присваивании
var y int64 = big         // тоже ок
```

### `iota` — генератор последовательных констант

`iota` — встроенный счётчик внутри блока `const`: он равен 0 в первой строке группы и
увеличивается на 1 с каждой следующей строкой. Это идиоматичная замена Java `enum`
для перечислений на основе целых.

**Паттерн 1: enum-подобные значения.**

```go
type Weekday int

const (
    Sunday Weekday = iota   // 0
    Monday                  // 1 (выражение "= iota" неявно повторяется)
    Tuesday                 // 2
    Wednesday               // 3
    Thursday                // 4
    Friday                  // 5
    Saturday                // 6
)
```

В отличие от Java `enum`, это **просто целые** с именованным типом `Weekday` — не объекты,
без методов «из коробки», без `values()`. Гарантий «только эти значения» компилятор не даёт:
`Weekday(99)` валиден. Часто к такому типу добавляют метод `String()` для печати (см.
[методы](./TYPES_STRUCTS_METHODS.md)).

**Паттерн 2: битовые флаги** (`iota` в сдвиге).

```go
type Permission uint

const (
    Read    Permission = 1 << iota   // 1 << 0 = 1
    Write                            // 1 << 1 = 2
    Execute                          // 1 << 2 = 4
)
// Проверка: if perms&Write != 0 { ... }
```

**Паттерн 3: единицы измерения** — пропуск значения через `_`.

```go
const (
    _  = iota             // пропускаем 0 (1<<0 == 1 байт нам не нужен как имя)
    KB = 1 << (10 * iota) // 1 << 10
    MB                    // 1 << 20
    GB                    // 1 << 30
    TB                    // 1 << 40
)
```

`iota` сбрасывается в 0 в **каждом новом** блоке `const ( ... )`.

## 4. Базовые типы

### Числа, bool, string

```go
// Целые со знаком:        int  int8  int16  int32  int64
// Беззнаковые:            uint uint8 uint16 uint32 uint64  uintptr
// Плавающая точка:        float32 float64
// Комплексные:            complex64 complex128
// Логический:             bool   (true / false)
// Строка:                 string (неизменяемая, UTF-8)
```

`int` и `uint` имеют **платформенно-зависимый размер** (64 бита на современных машинах,
32 — на 32-битных). Для сериализации и протоколов берут фиксированную ширину (`int64`,
`uint32`). По умолчанию для счётчиков и индексов — `int`.

Целочисленное деление и переполнение: `/` между целыми даёт целое (`7/2 == 3`); переполнение
**не паникует**, а заворачивается по модулю (как в Java). Деление на ноль для целых —
runtime-паника; для float — `+Inf`/`NaN`.

### `byte` = `uint8`, `rune` = `int32`

Два важных псевдонима, встроенных в язык:

| Псевдоним | Реальный тип | Смысл |
|-----------|--------------|-------|
| `byte` | `uint8` | один байт; элемент `[]byte`, «сырые» данные |
| `rune` | `int32` | один Unicode code point (символ), результат декодирования UTF-8 |

`string` в Go — это **неизменяемая последовательность байтов** (обычно валидный UTF-8), а не
последовательность `char`-ов как в Java (где `char` = 16-битный UTF-16). Индексация строки
`s[i]` даёт **байт** (`byte`), а не символ. Итерация через `range` даёт **руны** (символы)
вместе с их байтовым смещением. Подробно — в [строках, слайсах и maps](./SLICES_MAPS_STRINGS.md).

```go
s := "Привет"
fmt.Println(len(s))        // 12 — БАЙТ (кириллица = 2 байта/символ в UTF-8), не 6!
fmt.Println(s[0])          // 208 — первый байт, а не 'П'
for i, r := range s {      // r — руна (rune), i — байтовое смещение
    fmt.Printf("%d:%c ", i, r)
}
```

### Отсутствие неявных преобразований

Ключевое правило, на котором спотыкаются все, кто пришёл из Java/C: в Go **нет ни одного
неявного числового преобразования**. Даже `int` и `int64` несовместимы напрямую — нужна
явная конвертация `T(x)`.

```go
var i int = 5
var f float64 = 3.0

// var x float64 = i        // ❌ не компилируется: cannot use i (int) as float64
var x float64 = float64(i)  // ✅ явно
var n int = int(f)          // ✅ явно (дробная часть отбрасывается)

var a int32 = 1
var b int64 = 2
// c := a + b               // ❌ mismatched types int32 and int64
c := int64(a) + b           // ✅
```

Сравните с Java, где `long y = anInt;` работает молча (widening), а `int z = (int) aLong;`
требует каста только при сужении. Go требует **явности в обе стороны**: это убирает целый
класс тонких багов с потерей точности и неожиданным расширением. Единственное исключение —
нетипизированные константы (см. §3): литерал `5` подстроится под нужный тип сам.

## 5. Управление потоком

### `for` — единственный цикл

В Go нет `while` и нет `do-while`. Есть один `for`, у которого **нет круглых скобок** вокруг
условия (как и у `if`/`switch`), но тело **всегда** в фигурных скобках. Четыре формы:

```go
// 1. Классическая (init; condition; post)
for i := 0; i < 10; i++ {
    fmt.Println(i)
}

// 2. Только условие — это "while" из Java
sum := 1
for sum < 100 {
    sum += sum
}

// 3. Бесконечный цикл — это "while(true)"
for {
    if done() { break }
}

// 4. range — итерация по коллекции/каналу/числу
for i, v := range nums {   // индекс и значение
    fmt.Println(i, v)
}
```

`range` работает по слайсам, массивам, строкам (даёт руны), map (ключ+значение, **порядок
случаен**), каналам (только значения) и — с Go 1.22 — по целому числу (`for i := range 10`).
Если индекс не нужен — `for _, v := range nums`; если нужен только индекс — `for i := range nums`.

Важная ловушка переменной цикла (исторически частый баг): начиная с **Go 1.22** переменная
цикла создаётся **заново на каждой итерации**, поэтому замыкания и горутины захватывают
правильное значение. В Go ≤ 1.21 переменная была общей на весь цикл — классический источник
ошибок при `go func(){ use(v) }()`.

### `if` с init-стейтментом

`if` может содержать **короткий оператор инициализации** перед условием — переменная видна
только внутри `if`/`else`. Это основа главной идиомы обработки ошибок в Go:

```go
if err := doSomething(); err != nil {
    return err          // err видна только здесь
}
// err за пределами if не существует

if v, ok := cache[key]; ok {
    use(v)              // v и ok живут только в ветках if/else
}
```

**Идиома раннего возврата (early return).** В Go не делают глубоко вложенные `if/else`.
Ошибочные/граничные случаи проверяют первыми и сразу выходят, оставляя «счастливый путь»
без отступов:

```go
func process(data []byte) (Result, error) {
    if len(data) == 0 {
        return Result{}, errors.New("empty input")    // выход рано
    }
    parsed, err := parse(data)
    if err != nil {
        return Result{}, err                          // выход рано
    }
    return transform(parsed), nil                     // основной путь — без вложенности
}
```

### `switch` — гибче, чем в Java

`switch` в Go устроен иначе, чем в Java:

1. **Нет авто-`break`** — каждый `case` завершается сам, проваливания вниз по умолчанию нет
   (в Java забытый `break` — классический баг; в Go наоборот).
2. `case` может содержать **список значений** через запятую.
3. `fallthrough` — явный «провались в следующий case» (нужно редко).
4. **`switch` без выражения** — это элегантная замена цепочке `if-else-if`.
5. Поддерживает init-стейтмент, как `if`.

```go
switch day {
case Saturday, Sunday:        // список значений
    fmt.Println("выходной")
case Monday:
    fmt.Println("понедельник")
    fallthrough               // явно проваливаемся ниже
case Tuesday:
    fmt.Println("(или вторник)")
default:
    fmt.Println("будни")
}

// switch без выражения = if-else цепочка (читается лучше)
switch {
case score >= 90:
    grade = "A"
case score >= 80:
    grade = "B"
default:
    grade = "F"
}

// init-стейтмент в switch
switch os := runtime.GOOS; os {
case "darwin":
    fmt.Println("macOS")
case "linux":
    fmt.Println("Linux")
}
```

**Type switch** — особая форма `switch` для проверки динамического типа значения в интерфейсе
(`switch v := x.(type)`). Он неразрывно связан с интерфейсами, поэтому разбирается в
[INTERFACES.md](./INTERFACES.md).

### `goto`, метки, `break`/`continue` с метками

`goto` в Go существует, но применяется крайне редко (например, выход из глубоко вложенной
логики или генерируемый код). Гораздо чаще встречаются **метки (labels)** на циклах, чтобы
`break`/`continue` управляли **внешним** циклом — прямого аналога этому в Java тоже нет
в таком виде, но идея совпадает с Java labeled break:

```go
Outer:
for i := 0; i < n; i++ {
    for j := 0; j < m; j++ {
        if grid[i][j] == target {
            break Outer        // выйти СРАЗУ из обоих циклов
        }
        if skip(i, j) {
            continue Outer     // к следующей итерации ВНЕШНЕГО цикла
        }
    }
}
```

Без метки `break`/`continue` влияют только на ближайший цикл. `break` с меткой также
используется, чтобы выйти из `for` изнутри `select` (см.
[горутины и каналы](./GOROUTINES_CHANNELS.md)).

## 6. Функции

Функции объявляются через `func`. Тип параметра пишется **после** имени (`name type`) —
противоположно Java (`Type name`). Возвращаемый тип идёт после списка параметров.

```go
func add(a int, b int) int {
    return a + b
}

func add(a, b int) int { ... }   // если подряд тип одинаков — пишем его один раз
```

### Множественные возвраты и идиома `(value, error)`

Функция может вернуть **несколько значений** — это фундамент Go, а не экзотика. Главное
применение — пара `(результат, ошибка)`. В Go нет исключений (см.
[ERRORS_PANIC.md](./ERRORS_PANIC.md)); ошибка возвращается как обычное значение, и вызывающий
обязан её проверить.

```go
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("division by zero")
    }
    return a / b, nil    // nil error = успех
}

// Вызов — каноническая идиома:
result, err := divide(10, 2)
if err != nil {
    return err
}
use(result)
```

Это заменяет Java `throws`/`try-catch`: вместо «выбросить и поймать» — «вернуть и проверить».
Многозначный возврат используется и для `comma-ok` идиом: `v, ok := m[key]` (есть ли ключ
в map), `x, ok := i.(T)` (успешна ли type assertion).

### Named return values (именованные результаты)

Возвращаемым значениям можно дать имена. Тогда они работают как заранее объявленные
переменные (инициализированы в zero value), а `return` без аргументов («голый return»)
вернёт их текущие значения.

```go
func split(sum int) (x, y int) {   // x и y объявлены и равны 0
    x = sum * 4 / 9
    y = sum - x
    return                          // "голый" return: вернёт x, y
}
```

**Опасность named returns.** Это удобно для документирования (имена видны в сигнатуре) и
**необходимо** в одном случае — чтобы `defer` мог изменить результат функции, например в
`recover` (см. [ERRORS_PANIC.md](./ERRORS_PANIC.md)). Но «голый return» в длинной функции
сильно вредит читаемости: непонятно, что именно возвращается. Кроме того, легко случайно
затенить именованный результат через `:=` и вернуть не то. Правило: named returns уместны
в коротких функциях и там, где их меняет `defer`; в остальных случаях возвращайте значения явно.

### Variadic — переменное число аргументов

`...T` в последнем параметре означает «ноль или больше аргументов типа `T`». Внутри функции
это обычный `[]T` (слайс).

```go
func sum(nums ...int) int {      // nums имеет тип []int
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

sum(1, 2, 3)        // 6
sum()               // 0 — ноль аргументов допустимо
xs := []int{1, 2, 3}
sum(xs...)          // распаковка существующего слайса в аргументы
```

Это аналог Java varargs (`int... nums`), включая возможность передать готовый слайс через
`xs...` (как массив в Java). `fmt.Println(a ...any)` — самый известный variadic.

### Функции как значения и замыкания

Функции в Go — **полноценные значения** (first-class): их можно присваивать переменным,
передавать в аргументы, возвращать. **Замыкание (closure)** захватывает переменные из
окружающей области по ссылке.

```go
// функция как параметр
func apply(nums []int, f func(int) int) []int {
    out := make([]int, len(nums))
    for i, n := range nums {
        out[i] = f(n)
    }
    return out
}

// замыкание захватывает count
func counter() func() int {
    count := 0
    return func() int {   // замыкает count «по ссылке» — count живёт, пока жива функция
        count++
        return count
    }
}
c := counter()
c(); c()   // 1, затем 2
```

Это покрывает роль Java-лямбд и функциональных интерфейсов, но без `@FunctionalInterface` —
тип функции записывается прямо как `func(int) int`. Глубже (functional options, паттерны
`defer`-замыканий) — в [IDIOMS_PATTERNS.md](./IDIOMS_PATTERNS.md).

## 7. Экспорт: видимость по заглавной букве

В Go **нет ключевых слов `public`/`private`/`protected`**. Видимость определяется **первой
буквой имени**:

- Имя начинается с **заглавной** буквы → **экспортируется** (exported), видно из других
  пакетов. Аналог `public`.
- Имя начинается со **строчной** буквы → **не экспортируется** (unexported), видно только
  внутри своего пакета. Аналог package-private.

Это правило действует для **всего**: функций, типов, полей структур, методов, констант,
переменных пакетного уровня.

```go
package account

type Account struct {       // Account — экспортирован (виден снаружи)
    Owner   string          // Owner — экспортированное поле
    balance int             // balance — приватное поле (только внутри пакета account)
}

func New(owner string) *Account { ... }   // New — экспортированный конструктор
func (a *Account) Balance() int { ... }   // экспортированный геттер
func (a *Account) validate() error { ... } // validate — внутренний хелпер, снаружи невидим
```

Ключевое отличие от Java: **единица инкапсуляции — пакет, а не тип**. В Java `private`-поле
скрыто даже от других классов того же пакета; в Go код **внутри одного пакета** видит все
unexported-имена друг друга (разные файлы одного пакета — одно пространство). Граница
приватности проходит по пакету. Поэтому в Go нет геттеров/сеттеров «на всякий случай»:
если поле должно быть доступно — делают его заглавным; если нет — строчным. Идиоматичный
геттер называется `Balance()`, **а не** `GetBalance()` (приставка `Get` в Go не принята;
см. [IDIOMS_PATTERNS.md](./IDIOMS_PATTERNS.md)).

Особый случай — пакет `internal/`: всё под директорией `internal/` импортируется только
поддеревом, в котором он лежит (механизм уровня модуля). Подробности — в
[TOOLING_MODULES.md](./TOOLING_MODULES.md).

## 8. Минимальная программа и `go run`

Сложим всё вместе в одну работающую программу:

```go
// файл: main.go
package main

import (
    "fmt"
    "os"
)

func main() {
    if len(os.Args) < 2 {
        fmt.Fprintln(os.Stderr, "usage: greet <name>")
        os.Exit(1)
    }
    name := os.Args[1]
    fmt.Printf("Привет, %s!\n", name)
}
```

Запуск без явной компиляции в бинарь:

```bash
go run main.go Pavel        # компилирует во временный бинарь и сразу запускает
# Привет, Pavel!
```

Разница `go run` vs `go build`: `go run` компилирует во временный файл и исполняет (удобно
при разработке, ничего не остаётся на диске); `go build` создаёт постоянный исполняемый файл
в текущей директории. Toolchain (`go build/run/test/vet/fmt`) и go modules — отдельная тема в
[TOOLING_MODULES.md](./TOOLING_MODULES.md).

## Типичные ошибки

| Ошибка | Почему плохо | Как правильно |
|--------|--------------|---------------|
| Неиспользуемая переменная/импорт | не компилируется вовсе | удалить, либо `_` для переменной |
| `var x float64 = anInt` | нет неявных преобразований | `float64(anInt)` явно |
| `len(s)` ждали число символов | для UTF-8-строки это число **байт** | `utf8.RuneCountInString(s)` или `len([]rune(s))` |
| `s[i]` ждали символ | даёт **байт** (`byte`), а не руну | `for _, r := range s` |
| забыли проверить `err` | ошибка молча теряется | всегда `if err != nil` сразу после вызова |
| «голый» return в длинной функции | непонятно, что возвращается | возвращать значения явно |
| ожидание `break` в `switch` | в Go его не нужно, провала нет | `fallthrough` только если реально нужно |
| `GetBalance()` геттер | не идиоматично для Go | `Balance()` без `Get` |
| `package` не совпадает в файлах одной папки | ошибка компиляции | один `package` на директорию |
