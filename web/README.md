# Interview Prep — Web app

Single-user локальный сайт поверх `modules/` для:
- чтения теории с подсветкой и навигацией по roadmap;
- трекинга прогресса (read/known) по теории, упражнениям и Q&A;
- Anki-style повторения карточек (Leitner, 5 коробок) с авто-генерацией из `INTERVIEW_QUESTIONS.md` и ручным созданием;
- вечерних напоминаний через Web Push, чтобы очередь не копилась молча.

Контент берётся из `../modules/`. Прогресс — в PostgreSQL через Prisma: локально в контейнере из
`docker-compose.yml`, в проде на Neon. Задеплоено на Netlify.

## Запуск

```bash
cd web
pnpm install                                   # один раз
pnpm prisma migrate deploy                     # применить миграции (первый раз)
node_modules/.bin/tsx scripts/sync.ts          # импортировать контент
pnpm dev                                       # → http://localhost:3000
```

Тесты чистой логики (окно напоминаний, таймзоны, идемпотентность, протухшие подписки) —
без базы и без сети:

```bash
pnpm test
```

После правки файлов в `../modules/` — пере-импорт:

```bash
node_modules/.bin/tsx scripts/sync.ts
```

Sync идемпотентен: без изменений делает 0 записей. Прогресс и Leitner-стейт сохраняются через стабильные natural keys (`(moduleSlug, slug)` для теории/упражнений, `(moduleSlug, qNumber)` для Q&A).

## Что где

```

/modules/<slug>                   вкладки Обзор / Теория / Упражнения / Вопросы (?tab=)
/modules/<slug>/theory/<doc>      читалка: навигация · текст 720px · оглавление, плашки «Проверь
                                  себя» под разделами, панель вопросов
/modules/<slug>/exercises/<ex>    read-only код, Open in IDE
/modules/<slug>/qa                раскрывающиеся Q&A с per-Q "I know this"

/flashcards/triage                разбор завала: разложить / сбросить / заархивировать + дневной лимит
```

## Треки, разделы и привязка вопросов

**Треки.** 16 модулей сгруппированы в 5 треков (`lib/tracks.ts` — единственный источник; значение
пишется в `Module.track` из `content.config.ts` при sync): язык и рантайм, данные и хранение,
архитектура и проектирование, платформа и API, процесс и команда.

**Разделы теории.** `lib/theory-sections.ts` разбирает тело документа на разделы верхнего уровня
(`## `) — для оглавления, скролл-спая и позиции чтения. Якоря считаются тем же `lib/slugify.ts`,
что и рендерер с индексом поиска, иначе оглавление разъедется с текстом. Нумерацию `## N.`
используют 113 файлов из 199, поэтому номер раздела nullable: `index` есть всегда, `number` —
только у пронумерованных.

**Привязка вопроса к разделу.** Если `sourceRef` вопроса имеет вид `theory/FILE.md §N`, sync
раскладывает его в `refDocSlug`/`refSection`, и вопрос показывается плашкой «Проверь себя» прямо
под разделом. Префикс `theory/` обязателен: `JCP §6.3.2` и `JLS §17.4.5` — цитаты книг, а не
якоря. Номер раздела необязателен: `> theory/FILE.md` без `§N` привязывает вопрос к документу
(вкладка «Этот файл», счётчики на дашборде), но плашки в тексте не даёт.

**Что такое §N.** Номер из заголовка `## N. Заголовок`. Файл, где не пронумерован ни один
раздел, адресуется по позиции раздела — за это отвечает `TheorySection.refKey`
(`lib/theory-sections.ts`). Смешивать нельзя: если номер есть у части разделов, у остальных
`refKey = null` и сослаться на них невозможно — иначе позиция одного раздела совпала бы с
печатным номером другого.

**Покрытие.** 929 вопросов из 952 привязаны к разделу. Оставшиеся 23 — намеренно: блок
Applied Concurrency Patterns описывает упражнения, а не теорию (14); семь вопросов system-design
про сагу, Outbox и Event Sourcing, чья теория по правилу NO OVERLAP уехала в `microservices`;
два вопроса про кэш Hibernate, чей владелец — `hibernate-jpa` (ссылка резолвится только внутри
своего модуля).

**Плашка интерактивная.** Кроме «Показать ответ» в ней есть «Знал» / «Повторить» — те же
действия, что в очереди повторений (`reviewFlashcard` в `lib/actions.ts`), поэтому бокс и дата
следующего повтора двигаются прямо из читалки. Технически тело статьи режется на куски вокруг
точек вставки (`splitBySelfCheck` в `lib/markdown.tsx`), а между ними рендерится
`components/theory/SelfCheckCard.tsx`: внутрь строки HTML обработчики не положить.

**Проверка разметки** — без базы и без Prisma:

```bash
node_modules/.bin/tsx scripts/check-theory-refs.ts <slug>    # битые ссылки, вопросы без привязки,
                                                             # разделы без вопросов
node_modules/.bin/tsx scripts/check-theory-refs.ts --map <slug>   # карта разделов с диапазонами строк
```

Парсеры Q&A вынесены в `scripts/qa-parse.ts` и общие у импорта и у проверки — копия регулярок
разошлась бы с оригиналом на первой правке формата. Сам sync тоже ругается на промах:
`! bad theory ref: <module> Q<N> → …`, а в строке модуля печатает `linked N/M`.

Поиск живёт в шапке и доступен с любой страницы: `⌘K` / `Ctrl+K` или `/` — фокус,
`↑`/`↓` — перебор, `Enter` — переход, `Esc` — закрыть.

## Карточки и Leitner

5 коробок с интервалами:

| Box | Интервал |
|-----|----------|
| 1   | 1 день   |
| 2   | 3 дня    |
| 3   | 7 дней   |
| 4   | 14 дней  |
| 5   | 30 дней  |

- **«Знал»**: `box = min(5, box+1)`, streak +1, `nextDueAt = startOfTomorrow + interval`.
- **«Повторить»**: `box = 1`, lapses +1, streak = 0, `nextDueAt = startOfTomorrow`.

`startOfDay` берётся в локальной TZ — очередь стабильна независимо от времени review. Сегодняшняя
очередь сортируется `box ASC`. Размер очереди — `User.dailyReviewLimit` (если не задан, 50);
меняется тумблером на `/flashcards/triage`.

Очередь можно собрать из выбранных модулей: `/flashcards?decks=<slug>,<slug>`. Пустой параметр —
смешанная очередь из всех колод, `decks=none` — ничего не выбрано. Смешанная очередь остаётся
режимом по умолчанию намеренно: чередование модулей запоминается лучше, чем прогон одного подряд.

### Когда появляются новые карточки?

**Авто (из `INTERVIEW_QUESTIONS.md`):** каждый новый Q после `pnpm sync` создаёт карточку в box 1. При первичном sync `nextDueAt` раскидывается round-robin по 7 ближайшим дням, чтобы день 1 не утопил очередь. Дальше карточки появляются каждый раз когда:
- ты добавил новый `### Q<N>:` в `INTERVIEW_QUESTIONS.md` и сделал `pnpm sync` — она встанет на сегодня (далее по round-robin для anti-avalanche).
- ты создал manual-карточку через `/flashcards/new` — она встанет на сегодня (box 1).

При правке текста Q box/streak сохраняются, обновляется только front/back. Удалённые Q → карточка архивируется (`/flashcards/manage` с фильтром `archived = yes`).

## Напоминания, PWA и минимальная сессия

Главная проблема была не в расписании, а в том, что в приложение просто не заходят. Отсюда три
вещи, которые работают вместе: вечернее push-уведомление, короткий путь от него до карточки и
нарезка очереди на пачки по пять.

**Расписание Лейтнера при этом не изменилось.** Минимальная сессия — только про то, сколько
карточек показать за раз; каждая отвеченная проходит через тот же `reviewCard()`.

### Путь пользователя

```
20:30  🧠 14 карточек ждут повторения
       ~5 мин · начнём с 5
         │ тап
         ▼
       /review  →  первая карточка   (без выбора колод и режима)
         │ 5 карточек
         ▼
       🎉 Минимальная сессия завершена
       [ Продолжить ]  [ Закончить ]
```

`/review` — конечная точка и уведомления, и ярлыка установленного PWA (`start_url`).
`?all=1` — вся дневная очередь вместо пачки, `?round=N` — следующая пачка.
Выбор колод остался на `/flashcards`, он никуда не делся.

### Как устроена рассылка

```
netlify/functions/send-review-reminders.ts   @hourly, UTC
        │ POST + x-cron-secret
        ▼
app/api/reminders/run   →  lib/reminders.ts  (окно, таймзона, идемпотентность)
                        →  lib/push.ts       (web-push, снос протухших подписок)
```

Функция — тонкий триггер, вся работа в роуте: Prisma там уже собран плагином Netlify, а тащить
его нативный engine в esbuild-бандл отдельной функции пришлось бы вручную.

**Почему окно, а не точное время.** Cron ходит по UTC и раз в час: при напоминании на 20:30
ближайшие запуски — 20:00 и 21:00, и проверка «сейчас == 20:30» не сработала бы никогда.
Поэтому отправляем, если локальное время попало в `[20:30, 22:00)` — 90 минут. Заодно
переживает один пропущенный прогон.

**Почему не серверное время.** «20:30» означает 20:30 там, где находится человек. Зона берётся
из браузера (`Intl.DateTimeFormat().resolvedOptions().timeZone`) и хранится в `User.timezone`;
пересчёт — через `Intl`, а не арифметикой над смещением, иначе дважды в год ошибались бы на час
из-за перехода на летнее время.

**Идемпотентность.** После доставки пишется `User.lastReminderSentAt`, и следующий прогон в том
же окне отвечает `already-sent`. Отметка ставится только если хотя бы одно устройство реально
получило уведомление: при сетевой ошибке следующий прогон попробует снова. Отдельная страховка —
зазор в 12 часов: при напоминании около полуночи локальная дата сменяется внутри окна, и одной
проверки по дате не хватило бы.

**Протухшие подписки.** 404 и 410 от push-сервиса означают «подписки больше нет» → `active =
false`, прогон продолжается. Любая другая ошибка (5xx, обрыв) считается временной: подписку по
такому поводу не гасим, иначе одна авария у провайдера отписала бы навсегда.

Ответ роута — сводка, она же попадает в лог функции:

```json
{"checked":1,"sent":0,"skipped":[{"userId":1,"reason":"outside-window"}],"deactivated":0,"errors":[]}
```

Причины: `disabled`, `invalid-time`, `invalid-timezone`, `outside-window`, `already-sent`,
`no-due-cards`, `no-subscriptions`, `delivery-failed`.

### Настройка VAPID

```bash
node_modules/.bin/web-push generate-vapid-keys
```

Полученную пару разложить по переменным окружения (имена и пояснения — в `.env.example`):

| Переменная | Где живёт | Зачем |
|-----------|-----------|-------|
| `VAPID_PUBLIC_KEY` | сервер | подпись запроса к push-сервису |
| `VAPID_PRIVATE_KEY` | **только сервер** | в браузерный бандл не попадает |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | браузер | тот же публичный ключ, для `pushManager.subscribe` |
| `VAPID_SUBJECT` | сервер | `mailto:…`, требование протокола |
| `CRON_SECRET` | сервер | общий секрет функции и `/api/reminders/run` |
| `URL` | Netlify выдаёт сам | адрес сайта, куда стучится функция |

На Netlify: **Site configuration → Environment variables**. Локально — `.env.local`
(он в `.gitignore`).

Публичный ключ и должен быть в браузере — им подписывается подписка. Приватный читается только
в `lib/push.ts`, который импортируется исключительно server-side.

### Проверка вручную

Тестовое уведомление — кнопка на `/settings`: она проходит всю цепочку (подписка → база → VAPID
→ push-сервис → service worker → шторка), не дожидаясь вечера.

Прогон рассылки без Netlify CLI:

```bash
curl -i -X POST localhost:3000/api/reminders/run -H "x-cron-secret: $CRON_SECRET"
```

Второй такой же вызов подряд должен ответить `already-sent` — это и есть проверка
идемпотентности. Чтобы прислать ещё раз в те же сутки, на `/settings` есть «Сбросить отметку».

На задеплоенном сайте — `netlify functions:invoke send-review-reminders` (нужен залинкованный
сайт) либо кнопка запуска в Netlify UI → Functions. Расписание работает только для
опубликованных deploy'ов: локально `@hourly` не тикает.

### PWA

`app/manifest.ts` → `/manifest.webmanifest`, иконки в `public/icons/`, service worker —
`public/sw.js`.

Установка на Android: Chrome → меню → **Установить приложение**. После установки запускается в
standalone, `start_url` ведёт на `/review`.

Иконки генерируются из `app/icon.svg`:

```bash
node_modules/.bin/tsx scripts/gen-icons.ts
```

Три варианта не от избытка: обычная 192/512, отдельная maskable (лаунчер Android режет углы по
своей маске, поэтому там рисунок ужат в центральные 80%, а фон растянут на весь холст) и
монохромный badge для статусбара.

Service worker намеренно ничего не кэширует: всё содержимое динамическое, и закэшированная
страница показала бы вчерашние числа. Обработчик `fetch` там один и нужен для другого — без него
Chrome не считает приложение устанавливаемым.

`sw.js`, `manifest.webmanifest` и `icons/` исключены из матчера в `middleware.ts`: браузер
запрашивает манифест без учётных данных, и редирект на `/login` вместо JSON ломает установку.

## Тёмная/светлая тема

Кнопка `☀︎ Light / ☾ Dark` в правом верхнем углу. Запоминается в localStorage. Inline-скрипт в `<head>` применяет тему до первой отрисовки — флэш-эффекта нет.

Подсветка кода Shiki использует `github-dark-default` независимо от темы (фон блока всегда тёмный — общая практика для читаемости).

## Открытие файлов в IDE

В шапке упражнения/теории кнопка **«Open in IDE»** → POST `/api/open-in-ide` → сервер запускает `open -a "IntelliJ IDEA" <path>` (macOS). Работает во всех браузерах (включая Safari) и не требует JetBrains URL handler. Безопасно: путь должен лежать внутри `MODULES_ROOT`.

## Архитектура

**Стек:** Next.js 15 (App Router), React 19, Prisma 5 + PostgreSQL, Tailwind 3 + `@tailwindcss/typography`, Shiki, marked, web-push. Тесты — vitest.

**Модель данных:**
- `Module` (id, slug, title, order, track)
- `TheoryDoc` (moduleId, slug, title, body, order, isRead, sectionCount, readingMinutes)
- `Exercise` (moduleId, slug, number, title, body, language, isRead)
- `InterviewSection` + `InterviewQA` (moduleId, qNumber unique, isKnown, refDocSlug, refSection)
- `Flashcard` (source AUTO/MANUAL, qaId? FK, front, back, archived)
- `LeitnerState` (flashcardId unique, box, nextDueAt, streak, lapses)
- `ReviewLog` (история отметок)
- `PushSubscription` (endpoint unique, p256dh, auth, active) — подписка браузера на Web Push;
  плюс поля напоминаний в `User`: `remindersEnabled`, `reminderTime`, `timezone`,
  `lastReminderSentAt`

Авто-карточки имеют `qaId` → 1:1 с `InterviewQA`. При правке Q в .md sync обновляет front/back, но Leitner-стейт сохраняется через FK.

**Парсер `INTERVIEW_QUESTIONS.md`:** выбирается по `qaFormat` в `content.config.ts`. Три формата (см. CLAUDE.md в корне репо).

**Парсер ROADMAP.md:** ищет первое упоминание `theory/<NAME>.md` в roadmap и проставляет `TheoryDoc.order`. Не упомянутые файлы получают order=999 (в конец, дальше по алфавиту).

## Поиск

Ищет по **структуре** контента: концепты из `../knowledge/GLOBAL_INDEX.md` (994),
заголовки теории H2–H4 (4671), названия документов (199), вопросы Q&A (952), упражнения (53).
Тел статей в индексе нет.

**Почему так.** Приложение и база стоят в США, читатель — нет. Запрос в базу на каждое
нажатие клавиши стоил бы трансатлантического round-trip и нагружал Neon. Поэтому индекс
собирается заранее, отдаётся один раз и фильтруется целиком в браузере: **запросов к базе на
поиск — ноль**.

**Как устроено:**

- `scripts/sync.ts` попутно собирает `public/search-index.json` (~900 КБ, ~170 КБ под brotli).
  Отдельного прохода по `../modules/` нет — sync и так читает каждый файл, так что индекс не
  может разъехаться с тем, какие страницы реально существуют.
- Путь `search-index.json` исключён из матчера в `middleware.ts`, поэтому Netlify отдаёт его
  как обычный CDN-ассет с эджа рядом с читателем, а не функцией из США. Заголовок кэша задан
  в `next.config.mjs`: всегда ревалидировать, но тело перекачивать только после реальной правки.
- `components/SearchBox.tsx` тянет индекс лениво — на первом фокусе, один раз на вкладку
  (модульный синглтон переживает клиентские переходы). Ссылки результатов идут с
  `prefetch={false}`: иначе Next отрендерил бы на сервере каждую видимую строку выпадашки,
  вместе с её запросами в базу.
- `lib/search.ts` — матчинг и ранжирование, без React. Совпадение целого слова весит больше,
  чем начало более длинного (`cas` → «CAS», а не «cascade»). Запрос от 2 символов; токены
  длиной 2 засчитываются только на границе слова — иначе `gc` вытаскивал бы мусор.

**Якоря.** `lib/markdown.tsx` проставляет `id` заголовкам (`lib/slugify.ts`), а индекс
слагифицирует тот же текст в том же порядке — поэтому результат-заголовок попадает именно в
свою секцию. Q&A адресуется как `#qa-<qNumber>` — natural key, как и остальные ссылки в проекте.

Sync печатает предупреждение на каждый концепт `GLOBAL_INDEX.md`, чей модуль или файл не
нашёлся. Это заодно самая дешёвая проверка, что глобальный индекс не протух.

## Когда что-то ломается

| Симптом | Причина | Решение |
|---------|---------|---------|
| `pnpm dev` падает с `prisma generate` | engine binary не скачан | `node_modules/.bin/prisma generate` |
| После правки модуля ничего не меняется | sync не запущен | `node_modules/.bin/tsx scripts/sync.ts` |
| Q потерял Leitner-стейт | поменял `qNumber` в .md | Восстанови Q-номер либо смирись с потерей бокса |
| «Open in IDE» молчит | IntelliJ Toolbox не зарегистрировал app | проверить `which idea`; используется `open -a "IntelliJ IDEA"` |
| Поиск не находит новую теорию | индекс пересобирается только в sync | `node_modules/.bin/tsx scripts/sync.ts` |
| Результат-заголовок ведёт в начало страницы | якоря разъехались с рендером | заголовок правился без пересборки индекса — прогони sync |
| Вопрос не появился плашкой под разделом | ссылка `> theory/FILE.md §N` промахнулась мимо файла или номера | `tsx scripts/check-theory-refs.ts <slug>` — покажет битые ссылки и вопросы без привязки |
| Плашек нет во всём файле | в файле пронумерована только часть `##` | пронумеровать все содержательные разделы либо не нумеровать ни одного |
| Карточек завал на день 1 | massive add ставит все новые карточки на сегодня | `/flashcards/triage` → «Разложить по дням»; чтобы не собиралось снова — включить дневной лимит |
| Тумблер напоминаний не нажимается | не заданы VAPID-ключи либо браузер запретил уведомления | `/settings` пишет причину прямо на экране; разрешение сбрасывается только вручную, в настройках сайта |
| Тестовое уведомление: «Подписка устарела» | браузер выдал новую подписку (сброс разрешений, переустановка PWA) | выключить и снова включить напоминания — подписка перезапишется по тому же endpoint |
| Прогон отвечает `outside-window` | локальное время пользователя вне окна `[reminderTime, +90 мин)` | сверить `User.timezone` с реальной зоной; на `/settings` есть кнопка «Обновить» |
| Прогон отвечает `already-sent`, а уведомления не было | доставка прошла, но система его скрыла | на `/settings` «Сбросить отметку», затем проверить разрешения приложения в Android |
| Прогон отвечает `delivery-failed` | сеть или 5xx у push-сервиса; подписка не гасится | смотреть лог функции — там полная ошибка; следующий часовой прогон попробует снова |
| Уведомления не приходят при закрытом браузере | сайт открыт вкладкой, а не установлен | поставить PWA через «Установить приложение»; на iOS — «На экран „Домой“», iOS 16.4+ |
| Android не предлагает установку | манифест или воркер отдаются редиректом на `/login` | проверить исключения в матчере `middleware.ts` |
| `@hourly` не срабатывает локально | Scheduled Functions идут только на опубликованных deploy'ах | дёрнуть роут через `curl` (см. «Проверка вручную») |

## Игнорируется в git

`web/prisma/dev.db*` — твой прогресс не должен попадать в git, иначе будет конфликтовать между машинами.

`web/public/search-index.json` — генерируется из `../modules/`, в сборке пересоздаётся сам.

`web/.env` и `web/.env.local` — там боевые строки подключения и VAPID-ключи. Имена переменных
без значений лежат в `.env.example`, он как раз коммитится.
