# Контракт качества теории

Обязательные требования к любому файлу `modules/<slug>/theory/*.md` — и при создании нового модуля,
и при доработке существующего.

> **Зачем этот документ.** Теория, написанная «по памяти и по структуре API», закономерно
> вырождается в справочник: верные факты, аккуратные таблицы — и ноль объяснений. По такому тексту
> человек, не работавший с темой, не разберётся, а на собеседовании не сможет ответить на «почему».
> Хуже того, непроверенные утверждения устаревают молча: в этом репозитории аудит одного модуля
> нашёл 12 фактических ошибок, каждая из которых выглядела правдоподобно.
>
> Здесь зафиксировано то, что отличает объяснение от перечисления.

Читать вместе с: [`GLOSSARY.md`](GLOSSARY.md) (перевод), [`CANONICAL_TERMS.md`](CANONICAL_TERMS.md)
(терминология), [`GLOBAL_INDEX.md`](GLOBAL_INDEX.md) (владение концептами).

## 1. Обязательная структура файла

```markdown
# <Тема>

> **Какую проблему решает.** <конкретная ситуация, а не «даёт удобный API»>
> **Кому это надо.** <роль или ситуация — не «всем»>
> **Когда НЕ надо.** <когда этот инструмент — неправильный ответ>

<1–2 строки: что вынесено в соседние файлы, чтобы не искать. Ссылки относительные.>

---

## 1. <первый смысловой раздел — см. §2>
...

## N. Шпаргалка
<таблицы и «дерево решений» — сюда переезжает фактический материал>

## Упражнения
<ссылки на ../src/main/.../Ex<NN>_*.kt, если в модуле есть упражнения>

## Вопросы для самопроверки
<7–12 вопросов — см. §6>

## Источники
<спецификации / исходники с номерами строк / книги / разборы — см. §4>
```

**Шапка из трёх вопросов обязательна.** Если на «когда НЕ надо» нечего ответить — это признак,
что тема не понята, а не что инструмент универсален.

Проверка одной командой:

```bash
for f in modules/<slug>/theory/*.md; do
  head -12 "$f" | grep -q "Какую проблему решает" || echo "нет шапки: $f"
done
```

## 2. Схема смыслового раздела

Каждый раздел строится по четырём шагам. Пропуск любого превращает текст в справочник.

1. **Задача.** Конкретная ситуация: «надо сделать три сетевых вызова и собрать страницу».
2. **Наивное решение и где оно ломается.** С кодом и с последствием в цифрах или в поведении.
3. **Механизм.** Что происходит на самом деле — со ссылкой на исходник или на прогон.
4. **Правило.** Что из этого следует для повседневного кода.

### Как выглядит разница

❌ **Справочник** (реальный фрагмент до переработки):

> ### Цепочки — полная карта методов
> `thenApply(T→U) → CF<U>` · `thenCompose(T→CF<U>) → CF<U>` · `thenAccept(T→void)` …
> ⚠️ `thenApply` может выполниться в ЛЮБОМ потоке! Если нужна гарантия — используй `Async` вариант.

Факты верные. Но читатель не знает, **почему** «в любом», и запомнит это как каприз API.

✅ **Объяснение** (после):

> У `CompletableFuture` два поля: `result` и `stack` — стек зависимых действий.
> `thenApply` смотрит на `result`: если он уже есть — считает **прямо здесь, в вызывающем потоке**;
> если нет — кладёт узел на стек и возвращается. Завершающий поток снимает стек и всё выполняет.
>
> ```
> A. результата ещё нет:  thenApply в: завершитель
> B. результат уже есть:  thenApply в: main
> ```
>
> **Правило.** `thenApply` не выбирает поток — он выполняется там, где оказался результат.
> Значит, долгую работу туда класть нельзя: займёте чужой поток.

Тот же объём, но правило теперь **выведено**, а не заучено.

### Сквозной пример

У модуля должен быть один пример, проходящий через все файлы. Он даёт связность и позволяет
сравнивать подходы на одной задаче.

Примеры из репозитория:
- `concurrency` — «сервис на 1000 rps, запрос = три вызова по 100 мс»: из него выводятся размер
  пула, цена блокировки, ограничение нагрузки, виртуальные потоки.
- `kotlin-coroutines` — «загрузка профиля пользователя»: проходит через потоки → колбеки →
  futures → `suspend` → интероп.

## 3. Запрет на перечисление API

**Каталог методов — не теория.** Javadoc уже есть, и он полнее.

Если в файле появляется список из десяти вызовов подряд, у него должно быть одно из двух оправданий:

- это **шпаргалка в конце файла** (после того, как механизм объяснён), либо
- выбор метода **выводится из критерия**, а не даётся списком.

❌ Список:

```
thenApply · thenCompose · thenAccept · thenRun · thenCombine · thenAcceptBoth · applyToEither …
```

✅ Критерий выбора (таблица «что у вас на входе → что брать»):

| Ваша функция | Метод | Результат |
|---|---|---|
| `T → U` (значение) | `thenApply` | `CF<U>` |
| `T → CF<U>` (ещё один future) | `thenCompose` | `CF<U>` |
| `(T, U) → V`, два независимых источника | `thenCombine` | `CF<V>` |

Тот же принцип для «семейств» классов: не «вот пять синхронизаторов», а «вот какую координацию
каждый выражает» — и таблица, показывающая, что все пятеро суть один механизм с разным смыслом
одного поля.

## 4. Контракт достоверности

**Каждое утверждение о поведении подпирается одним из трёх, и это видно в тексте:**

| Опора | Как оформлять |
|---|---|
| Исходник | `// ConcurrentHashMap.java:560` — файл и номер строки; цитата дословная |
| Прогон | блок с **реальным** выводом + команда, которой он получен |
| Спецификация | ссылка на JLS/JEP/javadoc с точной формулировкой (цитатой, если она короткая) |

**Запрещено писать «известно, что», «обычно считается», «принято думать»** — это маркеры
непроверенного утверждения.

### Проверять до того, как написать

Правило простое: **если утверждение можно проверить за минуту — проверьте**. Что именно ловится
таким образом (примеры из реального аудита этого репозитория):

- «Structured Concurrency финализировано в Java 24» — на самом деле preview и в 21, и в 24;
  ловится одной командой `java STS.java`.
- «`sun.misc.Contended` доступен через `jdk.unsupported`» — класса нет с Java 9;
  ловится `Class.forName`.
- «`newWorkStealingPool` выполняет свои задачи LIFO» — фабрика передаёт `asyncMode = true`,
  то есть FIFO; ловится чтением `Executors.java:114`.
- «`ReentrantLock` быстрее при высокой конкуренции» — замер показал обратное.

Все четыре звучали правдоподобно и все четыре были неверны.

### Как оформлять замеры

```markdown
Замеры сняты на Apple M4 (10 ядер), Temurin 21.0.9. Это не JMH — порядок величин, а не бенчмарк.

```java
// CasRetry.java — java CasRetry.java
<минимальный воспроизводимый код>
```

```
потоков=8  попыток CAS на инкремент=4.66  284 мс
```
```

Обязательно: **машина и версии**, **оговорка про точность**, **команда для повторения**.
Замер без оговорки читается как измеренная истина и живёт дольше, чем железо, на котором снят.

Разброс не прячем: если значение плавает от прогона к прогону (`41–74 мс`), так и пишем — сам
разброс часто и есть содержательный факт.

## 5. Обязательные «отрицательные» разделы

Три вещи, которые почти всегда отсутствуют и почти всегда нужны:

1. **«Когда НЕ надо»** — в шапке файла. Инструмент, у которого нет границ применимости, описан
   неверно.
2. **«Чего этот инструмент не делает»** — снимает ложные ожидания.
   Пример: «`CompletableFuture` не превращает блокирующий вызов в неблокирующий»;
   «виртуальные потоки не ускоряют вычисления — ядер не прибавится».
3. **«Когда это неправильный ответ»** — внутри файла, для тем, которые берут по инерции.
   Пример: «`ConcurrentHashMap` для коллекции, которая не меняется после инициализации» —
   правильный ответ обычная `HashMap` плюс безопасная публикация.

Сюда же — **развенчание ходовых формулировок**, если тема ими обросла. Не «так тоже говорят»,
а прямо: «формулировка X описывает несуществующий механизм; на самом деле Y», с проверкой.

## 6. Вопросы для самопроверки

7–12 штук в конце файла. Проверяют **понимание механизма**, а не память на сигнатуры.

❌ «Какие методы есть у `Semaphore`?»
❌ «Что такое `CountDownLatch`?»

✅ «Что делает поток, если лок занят — по шагам, до момента, когда он перестаёт занимать процессор?»
✅ «Восемь потоков увеличивают общий `AtomicLong` и работают медленнее одного потока без
синхронизации. Где теряется время, если блокировок нет?»
✅ «Почему `size()` у `ConcurrentHashMap` приблизителен, а у `ConcurrentLinkedQueue` — O(n)?»

Хороший признак: на вопрос нельзя ответить, не прочитав раздел с механизмом.

Отдельно полезен блок **«формулировки, которые хорошо звучат»** — 3–5 фраз, которые читатель может
произнести на собеседовании: сжатая суть механизма одним предложением.

**Этот блок и `INTERVIEW_QUESTIONS.md` — разные вещи.** Здесь — проза без ответов, локальная для
файла: читатель проверяет себя сразу после чтения. Карточки для интервального повторения и плашки
«Проверь себя» в читалке берутся **только** из `modules/<slug>/INTERVIEW_QUESTIONS.md`, где у
каждого вопроса есть номер (natural key прогресса) и ответ. Разбирая тему, которую реально
спрашивают на собеседовании, заводи вопрос там — и привязывай его к разделу строкой
`> theory/FILE.md §N` (формат — в `CLAUDE.md`).

**Нумерация разделов.** Заголовки `##` содержательных разделов нумеруются (`## 4. Заголовок`) —
именно этот номер адресует §N в ссылках между файлами и в привязке вопросов. Служебный хвост
(`## Вопросы для самопроверки`, `## Источники`) остаётся без номера. Файл, где не пронумерован ни
один раздел, адресуется по позиции раздела; файл со смешанной нумерацией — частично не адресуем
вовсе, поэтому нумеруй либо всё, либо ничего.

## 7. Связность

- **Между файлами модуля** — ссылка ведёт на конкретный раздел, а не просто «см. также»:
  в тексте это выглядит как `FILE.md §4` со ссылкой на `FILE.md`.
- **На упражнения модуля** — блок «Упражнения» с относительными ссылками
  (`../src/main/kotlin/exercises/Ex08_Name.kt`). Web переписывает их в маршруты сайта
  автоматически. Теория без ссылок на упражнения — потерянная связь: их никто не найдёт.
- **На другие модули** — относительными путями (`../../<slug>/theory/FILE.md`), строго по
  правилу NO OVERLAP: концепт раскрывает владелец из [`GLOBAL_INDEX.md`](GLOBAL_INDEX.md),
  остальные ссылаются.
- **Сохранение фактического материала.** Переработка не означает выбрасывание: таблицы и списки,
  которые были в старой версии, переезжают в раздел «Шпаргалка» в конце — там они полезны при
  повторении.

## 8. Чек-лист приёмки файла

```
[ ] Шапка отвечает на три вопроса: проблема / кому / когда НЕ надо
[ ] Каждый смысловой раздел: задача → наивно и где ломается → механизм → правило
[ ] Нет каталогов API вне раздела «Шпаргалка»; выбор выводится из критерия
[ ] Каждое утверждение о поведении подпёрто исходником, прогоном или спецификацией
[ ] Все примеры кода реально скомпилированы и запущены; выводы в блоках — настоящие
[ ] Замеры: машина, версии, оговорка про точность, команда для повторения
[ ] Есть «чего инструмент не делает» и «когда это неправильный ответ»
[ ] Вопросы для самопроверки — про механизм, не про API
[ ] Ссылки на упражнения модуля и на соседние файлы; NO OVERLAP соблюдён
[ ] Термины по GLOSSARY.md и CANONICAL_TERMS.md; латиница только из раздела 1 глоссария
[ ] Ни одной битой ссылки
```

Последние два пункта проверяются автоматически:

```bash
# битые локальные ссылки
python3 - <<'PY'
import os, re, glob
for f in glob.glob('modules/<slug>/theory/*.md'):
    txt = re.sub(r'```.*?```', '', open(f, encoding='utf-8').read(), flags=re.S)
    for m in re.finditer(r'\[[^\]]*\]\(([^)#]+)', txt):
        t = m.group(1)
        if not t.startswith('http') and not os.path.exists(
                os.path.normpath(os.path.join(os.path.dirname(f), t))):
            print('БИТАЯ', f, t)
PY

# терминология
/check-translation <slug>
```
