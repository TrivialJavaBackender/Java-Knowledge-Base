# Глоссарий перевода

Канонический справочник терминологии для всех модулей репозитория (`theory/*.md`, `INTERVIEW_QUESTIONS.md`, `*.md` в корне модуля). Цель — единый, грамотный, естественный русский язык без латиничных вставок в теле текста.

> Правило применения: при добавлении нового концепта в любой модуль сначала свериться с этим документом. Если термина нет — обсудить с автором, добавить сюда, а потом использовать. Проверка: `/check-translation <module-name>`.

## 1. Оставляем как есть — стандарты индустрии

Эти термины — общепризнанные аббревиатуры или имена собственные. Пишутся латиницей в любом контексте, склонять не нужно (или склонение через дефис: «Kafka-кластер», «JWT-токен»).

### Имена паттернов надёжности и механизмов исполнения
circuit breaker, backoff, jitter, single-flight, cache stampede, dead-letter, fast path, work-stealing, token bucket, leaky bucket

Это имена конкретных паттернов и механизмов, а не описательные термины: перевод сделал бы их
неузнаваемыми (ср. Saga, Outbox, Raft). Русское пояснение допустимо в скобках при первом
упоминании — «повторы с экспоненциальной паузой (backoff)», — но основная форма латиницей.

### Имена механизмов JVM и конкурентности
happens-before, deadlock, livelock, lock-free, pinning, barging, spurious wakeup, mount / unmount, false sharing

Терминология модели памяти Java и Loom. Переводы либо не закрепились, либо теряют узнаваемость
в поиске и в чужом коде. Русское пояснение при первом упоминании уместно — «влезание без очереди
(barging)», «прибивание к носителю (pinning)», «ложное разделение (false sharing)», — дальше
основная форма латиницей.

### Имена практик, фреймворков и метрик процесса разработки
Scrum, Kanban, Scrumban, Waterfall, XP (Extreme Programming), SAFe, LeSS, Nexus, Shape Up,
trunk-based development, GitFlow, GitHub Flow, GitLab Flow, release train, blue-green, canary,
semver, Conventional Commits, Planning Poker, Monte Carlo, DORA, WSJF, RICE, ICE, MoSCoW, Kano,
WIP, DoD, DoR, CFD (cumulative flow diagram), error budget, cost of delay

Имена методологий, практик и оценочных моделей — это имена собственные: перевод делает их
неузнаваемыми и ломает поиск. Русское пояснение уместно при первом упоминании — «взвешенная
кратчайшая работа первой (WSJF)», «бюджет ошибок (error budget)», — дальше основная форма
латиницей. `error budget` идёт в паре с SLO/SLI из раздела «Метрики и инженерные сокращения».

### Имена ролей и артефактов Scrum
Product Owner, Scrum Master, Product Goal, Sprint Goal, Product Backlog, Sprint Backlog,
Definition of Done, Definition of Ready

Это термины спецификации (Scrum Guide 2020), а не описания должностей. Названия ролей
`Product Owner` и `Scrum Master` — латиницей и не склоняются («задача Product Owner», а не
«Product Owner'а»). Артефакты при первом упоминании дублируются русским: «бэклог продукта
(Product Backlog)», дальше — русская форма. `Developers` — обычное слово, переводится:
«разработчики».

## 5. Спорные случаи и комментарии

- **«heartbeat»** — оставляем латиницей в контексте Raft и health-check, потому что «сигнал жизни» звучит вычурно и не используется в индустрии.
- **«service mesh»** — отрасль не выработала русского эквивалента.
- **«feature store», «champion-challenger»** — то же самое, оставляем.
- **«push-уведомления»** — единственный случай, когда `push` оставлен; устоявшийся пользовательский термин.
- **«token bucket», «leaky bucket»** — оставляем как имена алгоритмов (с пояснением в скобках при первом упоминании).
- **«split-brain», «fan-out», «backpressure», «cache stampede», «failover», «handshake», «watermark»** — в скобках при первом упоминании в каждом файле, потом — русский вариант.
- **«vector clock» → «векторные часы»** (не «таймстампы»).
- **«atomic clocks» → «атомарные часы»** (не «атомные»).
- **«durability» → «живучесть»** (не «долговечность»).
- **«estimation» → «оценка»** (не «прикидка»).
- **«DC / datacenter» → «ЦОД»**.
- **«counter» → «счётчик»**.
- **«mitigation» → «способ защиты / противодействие»** (не «митигация»).
- **«linearizable» → «строгая согласованность (linearizable)»** при первом упоминании, потом — «строгая».
- **«tiebreaker» → «разрешение ничьей»**.
- **«ratio» → «отношение»**.
- **«recall» → «полнота»** (метрика поиска).
- **«rebuild» → «перестроение»**.
- **«collaborative filtering» → «коллаборативная фильтрация»**.
- **«content-based» → «на основе содержимого»**.
- **«max leading zeros» → «максимум ведущих нулей»**.
- **«surge» → «надбавка»** (с пояснением «surge» в скобках при первом упоминании в DESIGN_04).
- **«sloppy quorum + hinted handoff»** — оставить термины, при первом упоминании дать русскую расшифровку: «нестрогий кворум с подсказанной передачей».
- **«fencing token»** — оставить английский с пояснением «токен ограждения».
- **«joint consensus»** — оставить с пояснением «совместный консенсус».
- **«lease-based»** — заменить на «через временную аренду (lease)».
- **«join semilattice»** — оставить только при необходимости с пояснением «полурешётка слияния».
- **«leaderless multi-region»** — заменить на «multi-region без выделенного лидера».
- **«webhook»** — латиницей в каждом файле; не использовать вариант «вебхук» в одном файле с «webhook».
- **«backpressure» → «обратное давление (backpressure)»** при первом упоминании в файле, дальше — русский вариант (решение применено в модуле kotlin-coroutines).
- **«fan-out» / «fan-in» → «веерное распределение (fan-out)» / «веерное сведение (fan-in)»** при первом упоминании.
- **«graceful shutdown» → «плавное завершение (graceful shutdown)»** при первом упоминании, дальше — «плавное завершение».
- **«retry» → «повтор / повторы / повторные попытки»**; формы «ретраить», «ретраи», «ретрай» недопустимы. `retry` в обратных кавычках как имя оператора/функции — оставляем.
- **«confinement» → «confinement»** в связке «thread confinement»: имя приёма, русского эквивалента нет; при первом упоминании пояснять «доступ сериализован по построению».
- **«master / main»** — в тексте «основная ветка»; имя ветки внутри команд и путей (`git push origin main`) — как есть. Форма «мастер» как существительное недопустима.
- **«Definition of Done» → «критерий готовности (DoD)»**, «Definition of Ready» → «критерий готовности к работе (DoR)». Не «определение готовности»: это не определение, а согласованный список условий.
- **«commitment»** в Scrum Guide 2020 — «обязательство» (обязательство артефакта: Product Goal, Sprint Goal, Definition of Done), не «коммитмент» и не «приверженность».
- **«velocity» → «скорость команды (velocity)»**, не «производительность» и не «скорость разработки»: величина безразмерная и сравнима только с историей той же команды.
- **«capacity» → «ёмкость команды»** (сколько работы помещается), не «мощность» и не «пропускная способность» — последняя занята под `throughput`.
- **«utilization» → «загрузка»**, не «утилизация» (ложный друг: утилизация — это уничтожение отходов).
- **«root cause» → «первопричина»**, не «корневая причина» (калька); «root cause analysis» — «анализ первопричин».
- **«mitigation» инцидента → «устранение последствий»** — в отличие от общего правила «способ защиты / противодействие»: в разборе инцидента mitigation означает остановку ущерба до исправления первопричины.
- **«blameless postmortem» → «постмортем без поиска виноватых (blameless)»** при первом упоминании, дальше — «постмортем».
- **«error budget» → латиницей** (раздел 1), при первом упоминании в файле — «бюджет ошибок (error budget)». Решение отражает фактическое употребление в модуле infrastructure.
- **«cost of delay» → латиницей** с пояснением «стоимость задержки» при первом упоминании: это имя оценочной модели (Reinertsen), в паре с WSJF.
- **«trunk-based development», «GitFlow», «GitHub Flow», «release train»** — имена практик, не переводим; «trunk» отдельно от названия — «ствол (trunk)» или «основная ветка».
- **«canary» / «blue-green»** — «канареечная раскатка» и «сине-зелёное развёртывание» допустимы после первого упоминания латиницей; смешивать формы в одном файле нельзя.
- **«feature flag» → «флаг функциональности (feature flag)»** при первом упоминании, дальше — «feature flag» или «флаг». Форма «фича-флаг» недопустима.
- **«story point»** не переводим как «балл»: «стори-поинт», множественное — «стори-поинты».
- **«scope» → «объём работ (scope)»**; «out of scope» → «вне объёма работ»; «scope creep» → «расползание объёма (scope creep)».
- **«action item» → «экшен»** (закрепилось в контексте постмортемов и ретроспектив); при первом упоминании — «действие по итогам (action item)».
- **«severity» → «серьёзность (severity)»**; уровни `SEV1`/`SEV2`/`P0`/`P1` — как есть, латиницей.
